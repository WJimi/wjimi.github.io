# 小白学习项目指南

这份指南是给"没系统学过 C++、打开代码就发懵"的人写的。
目标不是让你成为 C++ 高手，而是让你**能读懂这个项目里的每一行代码，并且讲得出为什么这么写**。

## 这份指南怎么用

| 部分 | 内容 | 什么时候看 |
| --- | --- | --- |
| 第一部分 | 读代码需要的 C++ 语法 | 先看，遇到不认识的语法回这里查 |
| 第二部分 | 四个核心算法与两种构造过程精读 | 语法过一遍之后再看 |
| 第三部分 | 前置知识清单 | 检查自己漏了什么 |
| 第四部分 | 阅读顺序和自检题 | 最后做一遍 |

还有一个通用的读代码技巧，先记住：

> **把 `std::` 当成标点符号，直接跳过。**
> `std::cout` 在心里读成 `cout`，`std::vector<std::string>` 读成 `vector<string>`。
> 它不影响你理解逻辑，就像你不会去细看句号。

## 第一部分　读代码需要的 C++ 语法

这一部分只讲**这个项目里真正出现过的语法**，没出现的一个都不讲。
每小节都是同一个套路：先看你会遇到什么，再说它是什么意思，最后给项目里的真实例子。

### 1.1 速查表

先扫一眼混个脸熟，后面再逐个展开：

| 写法 | 读作 | 一句话解释 |
| --- | --- | --- |
| `#include <vector>` | 引入 | 把标准库的"变长数组"拿进来用 |
| `#include "trie.h"` | 引入 | 把同项目的 trie.h 拿进来用 |
| `struct TrieNode { ... };` | 结构体 | 把几个数据捆成一个整体 |
| `class Trie { ... };` | 类 | 数据 + 操作数据的函数，打包在一起 |
| `private:` | 私有 | 下面的东西只有自己能用 |
| `public:` | 公有 | 下面的东西外面也能用 |
| `TrieNode::TrieNode()` | 构造函数 | 新建一个东西时自动执行的函数 |
| `Trie::insert` | 归属 | insert 属于 Trie |
| `std::vector<int>` | 模板 | 一个装着 int 的变长数组 |
| `const std::string& s` | 引用 + 只读 | 直接用它别复制，而且不许改它 |
| `long* comparisons` | 指针 | 指向别处的变量，可以借它把结果传出去 |
| `it->first` | 箭头 | 指针或迭代器取成员用箭头，普通变量用点 |
| 参数后面的 `= 0` | 默认值 | 调用时不写这个参数，就当成 0 |

### 1.2 文件是怎么组织起来的

项目里每个模块都是**一对文件**：

```
trie.h    放"声明"——告诉别人有这么个东西，长什么样
trie.cpp  放"实现"——真正干活的代码
```

为什么要分开？因为 `main.cpp` 想用字典树，它只需要知道"有个类叫 Trie，有 insert 这个方法"，
不需要知道 insert 里面怎么写的。`.h` 就是这份"说明书"。

**你会看到头文件开头和结尾是这样：**

```cpp
#ifndef TRIE_H
#define TRIE_H
...
#endif
```

这三行叫**头文件保护**，意思是："如果 TRIE_H 这个记号还没定义过，就定义它然后编译下面的内容；
如果已经定义过，整段跳过。"

为什么需要？因为 `ac.cpp` 可能既直接 `#include "trie.h"`，又通过别的文件间接引入了 `trie.h`。
没有这三行，同一个 `class Trie` 会被定义两次，编译器直接报错。

`#include` 的两种写法也有讲究：

| 写法 | 去哪里找 | 什么时候用 |
| --- | --- | --- |
| `#include <vector>` | 标准库目录 | 用标准库的东西 |
| `#include "trie.h"` | 当前项目目录 | 用自己写的东西 |

### 1.3 struct：把几个数据捆成一个整体

**项目里的代码（trie.h）：**

```cpp
struct TrieNode {
    std::map<int, int> child;  // 字符编号 -> 子节点下标
    int fail;                  // 失配指针指向的节点下标
    int outLink;               // 输出链
    int wordId;                // 词尾标记
    int parent;                // 父节点下标
    int depth;                 // 深度
    int ch;                    // 走到本节点经过的那个字符
};
```

`struct` 就是"把一堆相关的数据打包成一个新类型"。定义完之后，
`TrieNode` 就和你熟悉的 `int`、`char` 一样，是一个类型名了。

这七行说的是："一个字典树节点，身上带着七样信息。"

**怎么用：**

```cpp
TrieNode n;           // 造一个节点
n.parent = cur;       // 用点号访问成员
n.depth  = 3;
```

点号 `.` 读作"的"——`n.parent` 就是"n 的 parent"。

**为什么这些信息要捆在一起？** 因为它们描述的是同一个东西。
如果拆成七个独立的数组，你得保证七个数组的第 5 号元素说的是同一个节点，
一旦哪里对不上，就会出现极难排查的 bug。捆成一个 struct 就不用操这个心了。

### 1.4 class、private、public —— 最该搞明白的三个词

**项目里的代码（trie.h）：**

```cpp
class Trie {
private:
    std::vector<TrieNode> pool;   // 所有节点都住在这里
public:
    Trie();
    int  insert(const std::string& word, int wordId);
    int  find(const std::string& word) const;
    bool remove(const std::string& word);
    int  size() const;
};
```

**先说 `class`。** 它和 `struct` 几乎是一回事，都是"把东西打包成一个新类型"。
区别只有一条，而且和你想的不一样——不是"struct 只能装数据、class 能装函数"，
两者都能装数据和函数。真正的区别是**默认权限**：

| 写法 | 不写 private/public 时，默认是 |
| --- | --- |
| `struct` | public，外面随便用 |
| `class` | private，只有自己能用 |

所以 `TrieNode` 用 struct（它就是一包数据），`Trie` 用 class（它要管住内部的节点池）。

**再说 private 和 public。** 这是整个项目最该理解的一个设计。

把 `Trie` 想象成一台机器：

- **public 是机箱面板上的按钮**——插词、查词、删除、看节点数，外面只能按按钮。
- **private 是机器内部的零件**——那个装着所有节点的 `pool`，外面碰不到。

所以下面第一种写法能编译，第二种会直接报错：

```cpp
Trie t;
t.insert("data", 0);      // 可以：按按钮
t.pool.push_back(node);   // 不行：pool 是 private，伸不进手
```

**为什么要把 pool 藏起来？** 因为它是整棵树的命根子：

- 节点的下标必须和它在 `pool` 里的位置一一对应。
  如果外面随手往 `pool` 里插一个或删一个，所有节点的 `child`、`fail` 里存的那些下标
  就全对不上了，整棵树瞬间变成一堆废引用。
- 藏起来之后，外面只能通过 `insert`、`find` 操作，而这些方法内部保证了"下标永远对得上"。

一句话：**private 不是为了保密，是为了保证数据不被用坏。**

**那 `setFail` 为什么是 public？** 因为它确实是给外面用的——AC 自动机要往节点上写失配指针，
而它属于另一个类，进不去 private。所以 Trie 特意开了一个"只能改 fail 这一个字段"的小口子，
而不是把整个 `pool` 敞开。这叫**开最小必要的口子**。

### 1.5 构造函数：新建东西时自动跑的函数

**项目里的代码（trie.cpp）：**

```cpp
TrieNode::TrieNode() {   // 名字和类型名一样，前面不写返回值类型
    fail    = -1;
    outLink = -1;
    wordId  = -1;
    parent  = -1;
    depth   = 0;
    ch      = 0;
}
```

名字和类型名相同、而且**不写返回值类型**的函数，就是构造函数。
它在"造一个新对象"的时候自动执行，你不用手动调用：

```cpp
TrieNode n;    // 这一行会自动去执行上面的 TrieNode::TrieNode()
```

**为什么需要它？** 因为 C++ 不会自动帮你把成员设成合理初值。
不写这个构造函数，`n.fail` 里可能是内存里残留的随机数，
于是"节点 3 的失配指针指向 18446744"这种莫名其妙的错误就来了。

这里把 `fail`、`wordId`、`parent` 都设成 -1，用的是项目里的统一约定：
**-1 表示"没有"**。因为节点下标是从 0 开始的非负数，-1 天然适合当"空"。

**还有一种写法你会看到（ac.cpp）：**

```cpp
AhoCorasick::AhoCorasick(Trie& t) : trie(&t) { }
```

冒号后面那截 `: trie(&t)` 叫**初始化列表**，意思是"用参数 t 的地址去初始化成员 trie"。
和写在花括号里效果一样，只是更直接。里面的 `&` 和 `&t` 到 1.7、1.8 节讲。

### 1.6 `::` 这个双冒号

`::` 叫作用域解析运算符，读作"**后面的东西属于前面的东西**"：

```cpp
Trie::insert        // insert 属于 Trie
TrieNode::TrieNode  // 构造函数属于 TrieNode
std::vector         // vector 属于 std（标准库命名空间）
std::map<int, int>::const_iterator   // 属于 map<int,int> 里面的迭代器类型
```

**为什么实现要写成 `Trie::insert` 而不是直接 `insert`？**
因为 `trie.cpp` 是独立的文件，编译器看到光秃秃的 `insert` 时并不知道你说的是哪个。
加上 `Trie::` 就明确了：这是 `Trie` 类里声明过的那个。

**顺带说 `std::` 和 `using namespace std;`。**
`std` 是标准库的命名空间，就是一个"名字的容器"，`std::cout` 意思是"std 里的 cout"。

别人代码里经常不写 `std::`，是因为他们在文件开头写了一行：

```cpp
using namespace std;   // 把 std 里所有名字倒进来，以后直接写 cout、string
```

这个项目**全程都写 `std::`**，原因有两条：

1. **头文件里绝对不能写 `using namespace std;`**。头文件会被很多 `.cpp` 包含，
   在里面写这一行，等于把"倒进来"这个动作强加给整个项目，别人没法拒绝。
2. 写整齐比省几个字母重要，而且看多了就习惯了。

### 1.7 引用 `&` 和 `const`

新手最容易懵的就是这里，因为 `&` 有两种完全不同的用法。

**用法一：取地址。**

```cpp
Trie t;
AhoCorasick ac(t);   // ac 内部：trie = &t;  把 t 的地址存进成员 trie
```

**用法二：声明一个引用。**

```cpp
int insert(const std::string& word, int wordId);
```

这里的 `const std::string& word` 拆成三段读：

| 部分 | 意思 |
| --- | --- |
| `const` | 我保证不改它 |
| `std::string&` | 引用：别复制一份，我就用你原来那个 |
| `word` | 参数名叫 word |

**为什么要用引用？** 因为字符串可能有几百个字符，按值传递会把整串复制一遍。
词库几千个词、文本几十万字符的时候，光复制就能把时间吃光。
引用就是"我不复制，直接递过去"。

**为什么要加 `const`？** 是给调用方一个承诺：这个函数不会偷改你的字符串。
有它之后，传常量进去也不报错；而且万一函数内部真改了，编译器会直接拦下来。

**你还会看到 `const` 写在函数尾巴上：**

```cpp
int size() const;   // 这个 const 说的是"这个函数不会改对象自己"
```

两种 const 的位置对照着记：

| 写法 | 约束的是谁 |
| --- | --- |
| `const std::string& word` | 参数 word 不许改 |
| `int size() const` | 这个对象自己的成员不许改 |

`find`、`size`、`node` 这些只读函数都带尾巴上的 `const`，
`insert`、`setFail` 这些会改数据的不带。这个规律能帮你一眼看出哪个函数会改数据。

### 1.8 指针 `*`

指针和引用的区别，一句话：**引用是别名，指针是地址。**

项目里有两处必须用指针，因为这两种情况都需要"可以指向空"：

```cpp
long* comparisons = 0;   // 参数：指向 long 的指针
Trie* trie;              // 成员：指向 Trie 的指针
```

```cpp
naiveSearch(text, words);        // 不传 comparisons
naiveSearch(text, words, &cmp);  // 传了，那就把比较次数写到 cmp 里
```

函数里对应的处理是：

```cpp
if (comparisons) *comparisons = cmp;   // 只有传了指针才写回去
```

`*comparisons` 里的 `*` 叫**解引用**，意思是"顺着这个地址找到真正的变量"。
所以 `*comparisons = cmp` 就是"把 cmp 的值写到那个地址里去"。

**`&` 和 `*` 是一对：`&x` 取地址，`*p` 按地址取值。**

```cpp
long cmp = 0;
long* p = &cmp;   // p 指向 cmp
*p = 5;           // 等价于 cmp = 5;
```

**点号 `.` 和箭头 `->` 的区别**，新手经常混：

```cpp
TrieNode n;
n.depth        // 手里是对象本身，用点号

Trie* t = &tree;
t->node(0)     // 手里是地址，用箭头，等价于 (*t).node(0)
```

规则很简单：**拿着对象本身就用 `.`，拿着它的地址就用 `->`。**

### 1.9 vector、string、map

这三个是标准库里最常用的容器，都是"能装东西、能自动扩容"的盒子。

| 容器 | 是什么 | 项目里拿来装什么 |
| --- | --- | --- |
| `std::vector<T>` | 能自动变长的数组 | 节点池、命中结果、字符序列 |
| `std::string` | 字符序列 | 关键词、待检测文本 |
| `std::map<K,V>` | 键值对表，按键排序 | 节点的孩子表：字符 → 子节点下标 |

常用操作长得几乎一样：

```cpp
std::vector<int> v;
v.push_back(5);   // 往末尾加一个
v.size();         // 有几个元素
v[0];             // 取第 0 个
v.empty();        // 是不是空的
```

`std::string` 也有 `size()`、`[]`、`push_back()`，用法一样。

**`map` 的查找写法要单独讲，因为它在项目里到处都是：**

```cpp
std::map<int, int> child;
if (child.find(cp) == child.end()) {
    // 没找到
}
```

`find(cp)` 返回指向这一项的迭代器；没找到就返回 `end()`。
所以 `find(...) == end()` 读作"找了一圈，到底了也没找着"，也就是**不存在**。
看到这个写法就条件反射读成"不存在"即可：

```cpp
if (pool[cur].child.find(cp) == pool[cur].child.end())   // 如果这个孩子还不存在
```

### 1.10 迭代器

迭代器是"用来遍历容器的指针"，你只要认识下面这几件事。

```cpp
for (std::map<int, int>::const_iterator it = rootKids.begin();
     it != rootKids.end(); ++it) {
    int v = it->second;
}
```

| 部分 | 意思 |
| --- | --- |
| `std::map<int, int>::const_iterator` | 专门遍历 `map<int,int>` 的迭代器类型，名字就是很长 |
| `it = rootKids.begin()` | 从第一个开始 |
| `it != rootKids.end()` | 只要还没走到末尾就继续 |
| `++it` | 走到下一个 |
| `it->second` | 取这一项的值 |

**`first` 和 `second` 是 map 每一项的两半：**

```cpp
it->first    // 键，这里是字符编号
it->second   // 值，这里是子节点下标
```

**为什么用箭头不用点号？** 因为迭代器本质上是个指针，
和 1.8 节说的一样，指针用箭头。

### 1.11 默认参数

```cpp
std::vector<MatchResult> naiveSearch(const std::string& text,
                                     const std::vector<std::string>& words,
                                     long* comparisons = 0,
                                     std::vector<AlignStep>* trace = 0,
                                     const RecordMask* mask = 0);
```

`= 0` 的意思是：**调用时可以不写这个参数，不写就当成 0。** 所以下面全合法：

```cpp
naiveSearch(text, words);              // 只要结果
naiveSearch(text, words, &cmp);        // 顺便要比较次数
naiveSearch(text, words, 0, &trace);   // 顺便要过程记录
```

这就是为什么同一个函数既能当纯算法用（跑得快），
又能当"会记录过程的算法"用（给可视化用）。**不传就不干活，没有额外开销。**

### 1.12 模板的尖括号

```cpp
std::vector<std::string> words;
std::map<int, int> child;
std::vector<std::vector<int> > ch;
```

尖括号里的东西叫模板参数，说白了就是**指定这个盒子装什么**：

```cpp
std::vector<int>               // 装 int 的变长数组
std::vector<std::string>       // 装字符串的变长数组
std::vector<std::vector<int> > // 装"变长数组"的变长数组，也就是二维数组
```

**注意最后一行 `> >` 中间有个空格。** 这是历史遗留：老标准的编译器看到连着的 `>>`
会当成右移运算符，以为你写错了。新标准已经修好，项目的代码保留了 `> >` 的写法，
当成 `>>` 看就行。

### 1.13 类型转换 `(int)`

```cpp
return (int)pool.size();
```

`(int)` 是强制类型转换：把后面的值转成 int。

**为什么到处都要转？** 因为 `size()` 返回的是 `std::size_t`，一个**无符号**整数。
无符号和有符号混着比较会出大问题：

```cpp
std::vector<int> v;                    // 空数组
for (int i = 0; i < v.size(); ++i)     // 危险
```

空数组的 `size()` 是 0，看起来没问题。但如果 `i` 是 -1，
它和无符号的 0 比较时会被当成一个巨大的正数，循环直接跑飞。
所以项目的习惯是**先转成 int 再比**：

```cpp
for (int i = 0; i < (int)pool.size(); ++i)
```

看到 `(int)` 就理解成"让两边类型一致，避免比较出错"。

### 1.14 匿名 namespace

**你会看到（matcher.cpp 开头）：**

```cpp
namespace {
void record(...) { ... }
void markHit(...) { ... }
}
```

没有名字的 namespace 叫匿名命名空间，作用是：
**这两个函数只有本文件能用，别的文件看不见。**

和 class 里的 private 有点像，都是限制使用范围，
只不过 private 管类的成员，匿名 namespace 管整个文件里的函数。
`record` 和 `markHit` 是给记录过程打下手的小工具，别的文件用不着，所以藏在本文件里。

### 1.15 lambda：就地写一个小函数

**你会看到（normalizeMatches）：**

```cpp
std::sort(hits.begin(), hits.end(),
          [](const MatchResult& a, const MatchResult& b) {
              if (a.start  != b.start)  return a.start  < b.start;
              if (a.length != b.length) return a.length < b.length;
              return a.wordId < b.wordId;
          });
```

`sort` 需要知道"怎么算谁在前谁在后"，中间那坨 `[](...) { ... }` 就是告诉它的规则。
这叫 lambda，也就是**就地写一个小函数，不用单独起名字**。

| 部分 | 意思 |
| --- | --- |
| `[]` | 捕获列表，这里是空的，表示不用外面的变量 |
| `(const MatchResult& a, const MatchResult& b)` | 要比较的两个元素 |
| `{ ... }` | 返回 true 表示 a 应该排在 b 前面 |

读成白话就是："先比起始位置，小的排前面；位置一样就比长度，短的排前面；都一样就比编号。"

紧跟着的 `unique` 用同一套写法，只不过它回答的是"a 和 b 算不算同一个"。

**为什么必须先排序再 unique？** 因为 `unique` 只合并**相邻**的重复项。
没排过序的数据，重复项东一个西一个，它看不见。

### 1.16 三个小语法

**三元运算符 `?:`**，是"如果…那么…否则…"的简写：

```cpp
return (pool[cur].wordId >= 0) ? cur : -1;   // wordId >= 0 就返回 cur，否则返回 -1
```

**for 循环的空条件**，中间判断留空表示"一直循环，靠 break 出去"：

```cpp
for (int v = cur; ; v = trie->node(v).fail) {
    if (v == 0) break;   // 出口在这里
}
```

**`-1` 表示"没有"**，这是项目里的统一约定。节点下标从 0 开始，
所以你会反复看到 `if (x < 0)`，读成"如果这个不存在"。

## 第二部分　核心算法与构造过程精读

四个算法按**从笨到巧**的顺序排：朴素 → KMP → 字典树 → AC 自动机。
前面的是后面的基础，建议按顺序看。看每个算法时盯住三个问题：

1. 它要解决什么问题？
2. 它比上一个算法聪明在哪？
3. 它付出了什么代价？

### 2.1 朴素匹配（BF）：最笨但最可靠的标准答案

**要解决的问题：** 在一段文本里，找出某个关键词出现的所有位置。

**做法：** 把关键词贴在文本的每一个位置上逐个字符比，对不上就整体右移一格再比。

**项目里的代码（matcher.cpp）：**

```cpp
std::vector<MatchResult> naiveSearch(const std::string& text,
                                     const std::vector<std::string>& words,
                                     long* comparisons,
                                     std::vector<AlignStep>* trace,
                                     const RecordMask* mask) {
    std::vector<MatchResult> hits;
    long cmp = 0;
    std::vector<int> t = utf8Decode(text);
    for (std::size_t w = 0; w < words.size(); ++w) {
        std::vector<int> p = utf8Decode(words[w]);
        if (p.empty() || p.size() > t.size()) continue;
        for (std::size_t i = 0; i + p.size() <= t.size(); ++i) {
            std::size_t j = 0;
            while (j < p.size()) {
                ++cmp;
                bool eq = (t[i + j] == p[j]);
                record(trace, (int)w, (int)i, (int)j, eq, eq ? 0 : 1, mask, (int)(i + j));
                if (!eq) break;
                ++j;
            }
            if (j == p.size()) {
                markHit(trace);
                MatchResult r;
                r.wordId = (int)w;
                r.start  = (int)i;
                r.length = (int)p.size();
                hits.push_back(r);
            }
        }
    }
    if (comparisons) *comparisons = cmp;
    normalizeMatches(hits);
    return hits;
}
```

**逐段读：**

```cpp
std::vector<int> t = utf8Decode(text);
```

把文本先解码成一串"字符编号"。`t` 是一个装着整数编号的数组，
`t[0]` 是第一个字符，`t[1]` 是第二个。
为什么不直接按字节比？因为那样一个汉字会被当成三个字节，位置全错——这就是前面修过的那个 bug。

```cpp
for (std::size_t w = 0; w < words.size(); ++w)
```

外层循环：**把词库里的每个词都拿出来试一遍**。这就是"单模式"的含义，一次只对一个词负责。
词库有 1000 个词，这一层就跑 1000 次。

```cpp
if (p.empty() || p.size() > t.size()) continue;
```

两句防御：空词跳过；比文本还长的词不可能出现，也跳过。
`continue` 是"这一轮不干了，直接跳到下一轮"。

```cpp
for (std::size_t i = 0; i + p.size() <= t.size(); ++i)
```

`i` 是**关键词贴在文本上的起始位置**，从 0 一直试到"再往后贴就超出文本"为止。

```cpp
std::size_t j = 0;
while (j < p.size()) {
    ...
    if (!eq) break;
    ++j;
}
```

`j` 是**已经对上了几个字符**。内层循环一个字符一个字符地比，
一旦对不上就立刻 `break` 跳出去。

```cpp
if (j == p.size()) { ... 记录命中 ... }
```

只有当 `j` 一路涨到关键词长度，才说明整个词都对上了。
**注意这里是 `==` 不是 `>=`**：`j` 要么中途 break 掉，要么正好等于长度。

**三个字段的含义：**

```cpp
r.wordId = (int)w;         // 命中的是词库里的第几个词
r.start  = (int)i;         // 从文本的第几个字符开始
r.length = (int)p.size();  // 命中了几个字符
```

**复杂度：** O(N × n × m)。`N` 是词库大小，`n` 是文本长度，`m` 是关键词长度。

**它凭什么还留在项目里？** 因为它**太好写了，几乎不可能写错**。
项目拿它当"标准答案"：随机生成数据，让另外两个算法跟它对比，对不上就说明另外两个写错了。
这个手法叫**对拍**。

### 2.2 KMP：让文本指针不再往回退

**朴素算法浪费在哪：** 关键词是 `ata`，文本是 `xatata`。
比到第三个字符失败之后，朴素算法会把关键词整个右移一格，从文本下一个位置重新比。
可是"前两个字符 `at` 已经比过了"这件事，它完全没记住。

**KMP 的想法：** 已经比过的部分里，藏着"下一次可以从哪里接着比"的信息。
把这些信息提前算好存进一个数组，匹配时直接查表。

**先算这张表：next 数组。**

```cpp
std::vector<int> kmpBuildNext(const std::vector<int>& p) {
    std::vector<int> next(p.size(), 0);
    int k = 0;
    for (std::size_t i = 1; i < p.size(); ++i) {
        while (k > 0 && p[i] != p[k]) k = next[k - 1];
        if (p[i] == p[k]) ++k;
        next[i] = k;
    }
    return next;
}
```

**`next[i]` 的含义：关键词前 `i+1` 个字符里，最长的"相等前后缀"有多长。**

这话绕，用例子说清楚。拿项目词库里的 `ata` 举例：

| i | 前 i+1 个字符 | 前后缀对比 | next[i] |
| --- | --- | --- | --- |
| 0 | a | 单字符没有真前后缀 | 0 |
| 1 | at | a 和 t 不等 | 0 |
| 2 | ata | a 和 a 相等 | 1 |

所以 `ata` 的 next 数组是 `[0, 0, 1]`。

**这个数字有什么用？** 它在说："如果我比到第三个字符才失败，说明前面 `at` 是配上的；
而 `ata` 的第一个字符和最后一个字符相同，所以下次可以直接从第二个字符接着比，
不用退回第一个。"

**代码怎么算出来的：**

```cpp
std::vector<int> next(p.size(), 0);
int k = 0;
for (std::size_t i = 1; i < p.size(); ++i) {
    while (k > 0 && p[i] != p[k]) k = next[k - 1];
    if (p[i] == p[k]) ++k;
    next[i] = k;
}
```

`std::vector<int> next(p.size(), 0)` 这种写法要认识一下：括号里第一个是"多大"，
第二个是"每个元素初始化成什么"。所以是"长度 p.size()、每个都是 0 的数组"。

**关键在于 `k` 的双重身份：** 它既是"已经配上的长度"，又正好是"下一个要比较的位置"。
因为前缀长度是 3 的话，下一个该比的字符下标正好就是 3。

**再看匹配：**

```cpp
std::vector<MatchResult> kmpSearch(const std::string& text,
                                   const std::vector<std::string>& words,
                                   long* comparisons,
                                   std::vector<AlignStep>* trace,
                                   const RecordMask* mask) {
    std::vector<MatchResult> hits;
    long cmp = 0;
    std::vector<int> t = utf8Decode(text);
    for (std::size_t w = 0; w < words.size(); ++w) {
        std::vector<int> p = utf8Decode(words[w]);
        if (p.empty() || p.size() > t.size()) continue;
        std::vector<int> next = kmpBuildNext(p);
        int k = 0;
        for (std::size_t i = 0; i < t.size(); ++i) {
            while (k > 0 && t[i] != p[k]) {
                ++cmp;
                int nv = next[k - 1];
                record(trace, (int)w, (int)i - k, k, false, k - nv, mask, (int)i);
                k = nv;
            }
            ++cmp;
            bool eq = (t[i] == p[k]);
            record(trace, (int)w, (int)i - k, k, eq, eq ? 0 : 1, mask, (int)i);
            if (!eq) continue;
            ++k;
            if (k == (int)p.size()) {
                markHit(trace);
                MatchResult r;
                r.wordId = (int)w;
                r.start  = (int)i - k + 1;
                r.length = (int)p.size();
                hits.push_back(r);
                k = next[k - 1];
            }
        }
    }
    if (comparisons) *comparisons = cmp;
    normalizeMatches(hits);
    return hits;
}
```

**和朴素算法对照着看，差别只有一处：**

朴素算法的内层要从 `j = 0` 重新开始比；KMP 的循环**只有文本位置 `i` 在往前走**，
从头到尾没有 `i--` 这种操作。每次失败时动的是 `k`（关键词往下退），而不是文本指针。

```cpp
for (std::size_t i = 0; i < t.size(); ++i)   // i 只加不减，这就是"文本指针不回退"
```

**这两段要重点看：**

```cpp
while (k > 0 && t[i] != p[k]) {
    ++cmp;
    int nv = next[k - 1];                    // 查表
    record(trace, (int)w, (int)i - k, k, false, k - nv, mask, (int)i);
    k = nv;                                  // 退到该退的位置
}
```

`next[k - 1]` 就是"已经配上的 k 个字符里，最长相等前后缀有多长"，
也就是"退到那里之后，前面这几个字符不用再比，直接接着往下"。

**注意是 `while` 不是 `if`**：可能退一次还不行，得连着退。

**这里有一个我自己踩过的坑，值得单独说：`record` 必须写在回退之前。**

第一版我把记录写在回退**之后**，结果页面上永远显示"模式串右移 1 格"，
看起来 KMP 和朴素算法一模一样。原因是：回退循环跑完之后，`k` 要么已经是 0、
要么就是这一格正好对上了，所以记下来的 `k` 永远是 0，算出来自然永远是挪一格。

而 KMP 和朴素算法的区别，恰恰发生在**退的那一瞬间**：
只有那一刻才知道"已经对上了 k 格、要退到 next[k-1]、可以一次跳过 k - next[k-1] 格"。
把这个瞬间漏掉，KMP 的优势就在画面上彻底消失了——算法没错，是观察它的方式错了。

**命中之后还要再退一次：**

```cpp
k = next[k - 1];
```

因为像 `ata` 这种词，可能在文本 `atata` 里连续出现两次，
找到一次之后不能就此停下，要退回去继续找下一次。

**复杂度：** 算 next 是 O(m)，匹配是 O(n + m)。
加上外层 N 个词，整体 O(N × (n + m))。比朴素的 O(N × n × m) 少了一个 m。

### 2.3 字典树（Trie）：让一堆词共享前缀

**要解决的问题：** 词库里几千个词，如果每个词都单独处理，太浪费。
能不能把它们**合并成一棵树**？

**想法：** 有共同前缀的词共用同一条路径。
`数据`、`数据库`、`数据结构` 前两个字符都是 `数据`，
那就让它们共用前两个节点，只在第三个字符处分岔。

**节点定义（trie.h）：**

```cpp
struct TrieNode {
    std::map<int, int> child;  // 字符编号 -> 子节点下标；一个汉字只占一格
    int fail;                  // 失配指针指向的节点下标；建树时先留 -1
    int outLink;               // 输出链：沿失配指针往上最近的"词尾节点"
    int wordId;                // 词尾标记：命中的词编号，-1 表示不是词尾
    int parent;                // 父节点下标，根为 -1
    int depth;                 // 深度；同时也等于它代表的字符串长度
    int ch;                    // 从父节点走到本节点经过的那个字符
};
```

这里有个**关键概念**：节点代表的不是"某个字符"，而是"**从根走到它的那条路径**"，
也就是一个**前缀**。

比如路径 `数 → 据` 对应的那个节点，它的意思是"前缀 `数据`"，而不是"字符 `据`"。
所以 `depth` 既表示"在第几层"，也表示"这个前缀有几个字符"。

**另外注意这里用整数下标代替了指针。** `child` 里存的是"子节点在数组里的位置"，
`-1` 表示没有。好处在 2.4 节末尾一起讲。

**插入一个词（trie.cpp）：**

```cpp
int Trie::insert(const std::string& word, int wordId) {
    std::vector<int> chars = utf8Decode(word);
    int cur = 0;
    for (std::size_t i = 0; i < chars.size(); ++i) {
        int cp = chars[i];
        if (pool[cur].child.find(cp) == pool[cur].child.end()) {
            TrieNode n;
            n.parent = cur;
            n.depth  = pool[cur].depth + 1;
            n.ch     = cp;
            pool.push_back(n);
            pool[cur].child[cp] = (int)pool.size() - 1;
        }
        cur = pool[cur].child[cp];
    }
    pool[cur].wordId = wordId;
    return cur;
}
```

**逐段读：**

```cpp
int cur = 0;   // 从根出发，根的编号固定是 0
```

```cpp
if (pool[cur].child.find(cp) == pool[cur].child.end())
```

1.9 节讲过的写法，读作**这个孩子还不存在**。

```cpp
TrieNode n;
n.parent = cur;
n.depth  = pool[cur].depth + 1;
n.ch     = cp;
pool.push_back(n);
pool[cur].child[cp] = (int)pool.size() - 1;
```

新建一个节点，填好信息，塞进数组池末尾，再让父节点记住它的位置。

`pool.size() - 1` 就是"刚塞进去的那个节点在哪儿"——因为 `push_back` 往末尾加，
所以它的下标一定是"加之前的大小"。

```cpp
cur = pool[cur].child[cp];
```

不管刚才是新建的还是本来就有的，总之往下走一层。

```cpp
pool[cur].wordId = wordId;
```

走完整个词之后，**在最后一个节点上盖个章**：这里是一个词的结尾。

**为什么要盖章，而不是用"叶子节点"来判断？** 因为节点 `at` 可能是词，
它下面还挂着 `ata`，所以它不是叶子。只按叶子判断的话，`at` 就被漏掉了。

**删除为什么只擦章、不删节点：**

```cpp
bool Trie::remove(const std::string& word) {
    int id = find(word);
    if (id < 0) return false;
    pool[id].wordId = -1;
    return true;
}
```

因为节点可能同时是别的词的前缀。删 `at` 的时候如果把节点也删了，
挂在它下面的 `ata` 就跟着没了。

**查一个词：**

```cpp
int cur = 0;
for (std::size_t i = 0; i < chars.size(); ++i) {
    std::map<int, int>::const_iterator it = pool[cur].child.find(chars[i]);
    if (it == pool[cur].child.end()) return -1;
    cur = it->second;
}
return (pool[cur].wordId >= 0) ? cur : -1;
```

和插入是同一条路，区别是走不通就直接返回 -1（不存在），
而且**走到头还要检查有没有词尾标记**——路径存在不等于这是个词。

**复杂度：** 建树 O(所有关键词的总长度)，查一个词 O(m)。

### 2.4 AC 自动机：一次扫描找出所有关键词

**前面还剩什么问题？** KMP 再快，也是"每个关键词扫一遍文本"。1000 个词就是 1000 遍。
AC 自动机的目标很明确：**不管词库多大，文本只扫一遍。**

**核心想法：** 在字典树上给每个节点补一条"退路"，
当前字符接不下去时就顺着退路往回跳，而不是回到根重新开始。

#### 第一步：建失配指针

```cpp
void AhoCorasick::buildFail() {
    trie->setFail(0, 0);
    trie->setOutLink(0, -1);
    std::queue<int> q;
    const std::map<int, int>& rootKids = trie->children(0);
    for (std::map<int, int>::const_iterator it = rootKids.begin();
         it != rootKids.end(); ++it) {
        int v = it->second;
        trie->setFail(v, 0);
        trie->setOutLink(v, -1);
        q.push(v);
    }
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        const std::map<int, int>& kids = trie->children(u);
        for (std::map<int, int>::const_iterator it = kids.begin();
             it != kids.end(); ++it) {
            int c = it->first;
            int v = it->second;
            int f = trie->node(u).fail;
            while (f > 0 && trie->childAt(f, c) < 0) f = trie->node(f).fail;
            int t = trie->childAt(f, c);
            if (t >= 0 && t != v) f = t;
            else                  f = 0;
            trie->setFail(v, f);
            if (trie->node(f).wordId >= 0) trie->setOutLink(v, f);
            else                           trie->setOutLink(v, trie->node(f).outLink);
            q.push(v);
        }
    }
}
```

`std::queue<int> q` 是需要新认识的容器：**队列**，先进先出。

| 操作 | 意思 |
| --- | --- |
| `q.push(v)` | 从尾巴上塞一个进去 |
| `q.front()` | 看队头那个 |
| `q.pop()` | 把队头拿掉 |
| `q.empty()` | 是不是空的 |

**为什么要用队列？** 因为失配指针必须**按层**算：

> 算一个节点的失配指针，要用到它父节点的失配指针。父节点层数浅、子节点层数深，
> 所以按层推进，用到的时候一定已经算好了。

队列正好是先进先出：把第一层放进去，算完第一层自然轮到第二层。这就是**广度优先遍历**。

**换成深度优先会怎样？** 很可能算到子节点时父节点的失配指针还是空的，结果就是错的。

**核心那五行：**

```cpp
int f = trie->node(u).fail;              // 从父节点的失配指针出发
while (f > 0 && trie->childAt(f, c) < 0) // 谁有 c 这个孩子？
    f = trie->node(f).fail;              // 没有就继续往上找
int t = trie->childAt(f, c);
if (t >= 0 && t != v) f = t;             // 找到了，就是它
else                  f = 0;             // 找到顶还没有，回根
```

**这两行是"输出链"，是本项目比教科书多做的一步：**

```cpp
if (trie->node(f).wordId >= 0) trie->setOutLink(v, f);
else                           trie->setOutLink(v, trie->node(f).outLink);
```

它记的是"从我这个节点往上，最近的一个是词的祖先是谁"。
有了它，匹配时找命中就不用一个节点一个节点地爬整条失配链，
可以直接跳到下一个真正的词。这一步让匹配从"和链长成正比"
变成"和命中数成正比"，复杂度里的 O(n + z) 才真正成立，而不是照抄课本。

#### 第二步：匹配

```cpp
std::vector<MatchResult> AhoCorasick::match(const std::string& text,
                                            std::vector<MatchStep>* trace,
                                            long* jumps,
                                            const RecordMask* mask) const {
    std::vector<MatchResult> hits;
    long jumpCount = 0;
    std::vector<int> chars = utf8Decode(text);
    int cur = 0;
    for (std::size_t i = 0; i < chars.size(); ++i) {
        int cp = chars[i];
        while (cur > 0 && trie->childAt(cur, cp) < 0) {
            cur = trie->node(cur).fail;
            ++jumpCount;
        }
        int nxt = trie->childAt(cur, cp);
        if (nxt >= 0) cur = nxt;
        for (int v = cur; v >= 0; v = trie->node(v).outLink) {
            if (trie->node(v).wordId >= 0) {
                MatchResult r;
                r.wordId = trie->node(v).wordId;
                r.length = trie->node(v).depth;
                r.start  = (int)i - r.length + 1;
                hits.push_back(r);
            }
        }
    }
    normalizeMatches(hits);
    if (jumps) *jumps = jumpCount;
    return hits;
}
```

**这段和 KMP 像不像？** 循环是 `for (i = 0; i < chars.size(); ++i)`，
**文本指针从头到尾只增不减**，动的只有 `cur`。这就是"文本只扫一遍"的含义。

> 上面这段为了好读，删掉了记录过程那几行（`if (trace) ...` 和 `keep` 相关的判断）。
> 那几行只跟"生成网页动画"有关，不影响匹配本身，
> 打开 `src/ac.cpp` 时会看到它们，可以对照 1.11 节理解。

```cpp
while (cur > 0 && trie->childAt(cur, cp) < 0) {
    cur = trie->node(cur).fail;    // 接不下去，顺着退路往回跳
    ++jumpCount;
}
int nxt = trie->childAt(cur, cp);
if (nxt >= 0) cur = nxt;           // 能接上就走过去
```

**命中检查为什么要沿输出链走一圈？**

因为"当前这个节点不是词"不等于"没有命中"。举个项目里的例子：
词库里有 `data` 和 `ata`，文本走到 `data` 的最后一个 `a` 时，
脚下这个节点代表 `data`（是词），而它的失配指针指向代表 `ata` 的节点，**`ata` 也是词**。
所以这一步要同时报出两个命中。

只检查脚下那一个节点，就会漏掉一半的结果——这是 AC 自动机最经典的错误。

**起点怎么算：**

```cpp
r.length = trie->node(v).depth;      // 节点深度就是这个词的长度
r.start  = (int)i - r.length + 1;    // 当前位置减长度再加一
```

因为 `depth` 同时表示"这个前缀有几个字符"，所以不用另外存词长。

**复杂度：** 建树 O(L)，L 是词库总长度；建失配指针 O(节点数)；
匹配 O(n + z)，n 是文本长度，z 是命中数。**和词库大小 N 无关**——
这就是词库越大、它的优势越大的原因。

#### 顺带说"数组池"

项目的节点全部存在一个 `std::vector<TrieNode>` 里，节点之间用整数下标互相引用，
全程没有 `new` / `delete`。好处是：

| 好处 | 说明 |
| --- | --- |
| 不会内存泄漏 | 没有手动申请的内存 |
| 不会野指针 | 引用的是下标不是地址，调试时可以直接看 `pool[5]` 长什么样 |
| 删除变简单 | 删词只要把 `wordId` 改成 -1，一个节点都不用释放 |

**唯一要小心的地方**（代码里也写成了注释）：`pool.push_back()` 之后数组可能搬家，
所以**不能提前存一个指向某个节点的引用或指针、之后还接着用**。
项目里全程用下标访问，就避开了这个坑。

### 2.5 两种“构造过程”是怎么记录下来的

项目不仅能回放“怎么匹配”，还能回放两个数据结构**怎么建出来**。
这部分不是新增算法，而是在算法执行时多存一份过程记录。
理解它以后，`visualize.cpp` 里那两大段 JS 就不再像黑箱。

#### 2.5.1 KMP 建 next：模式串拿自己跟自己比

`kmpBuildNext` 本来就一边计算、一边得到 next 数组。为了演示，
项目在每次比较后追加一条 `NextStep`：

```cpp
struct NextStep {
    int  i;        // 正在算 next[i]
    int  k;        // 拿模式串第 k 格去比
    bool equal;    // 这一格是否相同
    int  written;  // 这一步写完 next[i] 的值；-1 表示只是回退
};
```

把模式串同时看成“主串”和“模式串”：

- 上面一行是主串，位置就是模式串自己；
- 下面一行是模式，头部对齐到当前位置减 `k`；
- 每比较一次，页面追加一格记录；
- `while` 里发生回退时，`written = -1`，演示只移动对齐位置，不写 next；
- 比较结束后，页面把 `next[i]` 填进表格。

页面会一次性生成从 `next[0]` 到 `next[m-1]` 的全部格子，不会再用
“只显示当前格附近几格”的省略号方案。格子宽度固定，三行仍然一一对齐；
数组短时直接铺开，超过可视宽度时才让整个三行区域横向滚动。这样既不会把
很长的关键词压缩到看不清，也不会让滚动范围脱离对应的字符位置。

关键不是多写了几行记录，而是**记录点必须放在状态改变之前**。
如果先执行 `k = next[k - 1]` 再记录，原来已经匹配了几格已经丢了，
页面上就只能看到“每次挪一格”，看不到 KMP 的跳跃。

#### 2.5.2 AC 建失配：沿树往上找退路

建 fail 时，每确定一个孩子 `v` 的失配指针，记录一条 `FailStep`：

```cpp
struct FailStep {
    int              u;         // 从队列取出、正在处理孩子的节点
    int              v;         // 正在确定 fail 的孩子
    std::string      ch;        // u 到 v 经过的字符
    std::vector<int> walk;      // 沿失配链往上找时经过的节点
    int              failTo;    // 最后确定的 fail[v]
    int              queueLeft; // 队列里还剩多少节点
};
```

页面拿到一条记录后：

1. 把 `u` 标成“正在处理”；
2. 把 `v` 标成“要定 fail 的节点”；
3. 按 `walk` 的顺序逐个高亮爬过的节点；
4. 在 `v` 和 `failTo` 之间画出这一步确定的红色箭头；
5. 状态栏显示队列还剩多少节点，说明当前推进到哪一层。

所以“AC建失配”不是另一套算法，只是把 `buildFail()` 本来就会发生的
“从 `fail[u]` 开始找字符 `ch` 的孩子”如实记录下来。

#### 2.5.3 为什么要限制演示规模

记录本身会增大网页体积，树太大时眼睛也看不清。项目用两个常量控制提示：

```cpp
const int FAIL_MAX_NODES = 50;  // 树节点不超过 50 个，AC 建失配才好看
const int NEXT_MIN_LEN   = 6;   // 关键词至少 6 个字符，next 演示才不空
```

这是“可读性建议”，不是算法限制。控制台加载词库后会显示建议，
网页进入对应模式时也会显示同样的提醒。

### 2.6 四个算法放在一起比

| 算法 | 文本要扫几遍 | 匹配复杂度 | 项目里拿它干什么 |
| --- | --- | --- | --- |
| 朴素 BF | N 遍 | O(N·n·m) | 当标准答案，给对拍用 |
| KMP | N 遍 | O(N·(n+m)) | 说明"文本指针不回退"能带来什么 |
| 字典树 | 不匹配文本 | — | 前三个算法的地基，也是 AC 的骨架 |
| AC 自动机 | **1 遍** | O(n + z) | 真正干活的那个 |

`N` 是词库大小，`n` 是文本长度，`m` 是单词长度，`z` 是命中数。

项目里 `bench` 模块的两组实验验证的就是这张表：

| 实验 | 固定什么 | 放大什么 | 会看到什么 |
| --- | --- | --- | --- |
| 实验一 | 词库 | 文本 | 三种算法都变慢，差距比例大致稳定 |
| 实验二 | 文本 | 词库 | 朴素和 KMP 线性变慢，**AC 几乎不动** |

实验二才是关键——它把"文本只扫一遍"这句话变成了屏幕上的数字。

## 第三部分　前置知识清单

这一部分是原来那份《前置知识清单》，现在并进本指南。
判断标准只有一条：**每一项都要能用一句话讲出来，而不是"看着眼熟"。**

### A 级：不知道就真的会失控

A 级是 AC 自动机的全部理论。答不上来，项目就真的会失控。

**A1　树的术语**
根、父节点、子节点、深度、路径、叶子。
*自检：说出某个节点的父节点、深度，以及从根到它的路径。*

**A2　前缀、后缀、真后缀**
*自检：`data` 的所有真后缀是哪些？其中哪些同时是词库里某个词或某个节点的前缀？*

**A3　字典树的核心性质**
节点代表的是"从根到该节点的路径"，也就是一个前缀，不是单个字符。
*自检：`data` 和 `ata` 在树里共享了节点吗？共享了哪几个？*

**A4　词尾标记**
*自检：如果改成"没有子节点的节点才算词尾"，词库里的 `at` 会不会被漏掉？为什么？*

**A5　失配指针的准确含义**
`fail(v)` 指向：节点 v 所代表前缀的**最长真后缀**，并且这个后缀必须是树中某个节点的前缀。
*自检：用一句话解释某个节点的失配指针为什么指向它而不是别的节点。*

**A6　为什么必须按层构建**
*自检：计算一个节点的失配指针时用到了哪个节点的失配指针？这两个节点的深度是什么关系？*

**A7　命中回溯（本项目用"输出链"实现）**
走到一个节点之后，不能只看脚下，还要继续找词尾祖先，
因为失配链上每个节点代表的都是"已匹配串的一个真后缀"。
*自检：为什么走到 `data` 的末尾能同时命中 `data` 和 `ata`？*

**A8　文本指针不回退**
匹配时文本下标只增不减，所有回退都发生在树上。
*自检：匹配文本的第 5 个字符时，自动机跳了几次？文本下标动了吗？*

> A1 到 A8 都能答上来，AC 自动机对你来说就没有黑箱了。

### B 级：用错会写出慢的或错的代码

**B1　队列与广度优先遍历**
构建失配指针的载体。
*自检：为什么广度优先天然适合"按层处理"？*

**B2　复杂度分析**
朴素 O(N·n·m)，KMP O(N·(n+m))，AC 自动机 O(n+z)。
`N` 词库大小，`n` 文本长度，`m` 单词长度，`z` 命中数。
*自检：为什么 AC 自动机的匹配阶段和词库大小 N 无关？*
*提示：它把"每个词扫一遍"换成了"文本扫一遍 + 树上跳转"。*

**B3　字符编码与 UTF-8**
UTF-8 是变长编码，一个汉字通常占 3 个字节。
*自检：为什么必须先把字节解码成字符再处理？直接按字节比会出什么问题？*
*提示：一个汉字会被当成三个"字符"，位置全错，树上还会出现半个字。*

**B4　C++ 的 string 与 vector**
`size()` / `[]` / `push_back()` / `empty()` 这些基本操作。
*自检：`size()` 返回的是什么类型？为什么项目里到处写 `(int)` 再比较？*

**B5　指针与内存管理（本项目用数组池规避）**
*自检：项目里为什么一个 `new` 都没有？这样做避开了哪些坑？*

### C 级：知道有这回事就行，用时现查

- **C1　文件读写**：`ifstream`、`getline`、判断文件是否打开成功。
- **C2　递归与后序遍历**：画树时用来自底向上计算节点坐标。
- **C3　编码与转义**：源文件存成 UTF-8；网页里的转义要分清 HTML 和 JS 两种场合。

### 4.3 一句话总结整个项目

把词库建成一棵共享前缀的树，在树上给每个节点配好退路，
然后让文本从树上一路走过去，一次就把所有关键词都找出来。
前面两个单模式算法留着，是为了当尺子——量出后面这个到底快了多少。
