# 宇宙微波辐射 WriteUp

> 题目附件：`Secrets of the Cosmic Microwave Background.mkv`（以及从 MKV 中提取出的 `g2.tar`、`g4.tar`）
> 
> `flag{S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m}`

---

## 0. 先说结论

这道题的核心不是常规的 LSB、文件尾追加或明文 `strings`，而是：

1. MKV 容器里除了正片，还藏着**第二条视频轨、一条“假字幕”轨和两个附件**；
2. 这些雪花帧里藏着**文字**，但文字不是直接画上去的，而是通过“成对帧之间像素完全相同”这一特征暴露出来的；
3. 各个数据源的名字（`g2`、`g4`）就是**组号提示**，决定了文字片段的拼接顺序；
4. 正片结尾 PBS logo 之后还有一段约 8 秒的电视雪花，藏着最后一个词 `stream}`。

把这些片段按 `g1 → g2 → g3 → g4 → g5` 拼接，再补上正片结尾雪花里的 `5tr34m}`，就得到完整字符串：

```
f1a9{S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m}
```

其中 `f1a9{` 是 leet 写法的 `flag{`。按平台要求的 `flag{}` 前缀提交，最终为：

```
flag{S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m}
```

它还原成英文是：

> **Secret of CMB hidden inside stream**
>
> （CMB 的秘密藏在流里）

---

## 1. 查看 MKV 的“套娃”结构

先用 `ffmpeg` 直接看容器里有什么：

```bash
ffmpeg -hide_banner -i "Secrets of the Cosmic Microwave Background.mkv"
```

关键输出：

```text
Stream #0:0: Video: h264 ..., 1280x720, 23.98 fps        # 正片
Stream #0:1(eng): Audio: aac, 44100 Hz, stereo           # 音频
Stream #0:2: Video: h264 ..., 1280x720, 0.39 fps         # 第二条视频轨：雪花
Stream #0:3: Subtitle: subrip                            # 字幕（内有玄机）
Stream #0:4: Attachment: none                            # g2.tar
Stream #0:5: Attachment: none                            # g4.tar
```

也就是说，这个 MKV 不是普通视频：

- **第 0 条流**：真正的纪录片正片（17 分钟）；
- **第 1 条流**：AAC 音频；
- **第 2 条流**：一条极低帧率（约 0.388 fps）的 720p 雪花视频，共 400 帧；
- **第 3 条流**：字幕轨，但它的“字幕文本”其实是十六进制数据；
- **附件 4/5**：`g2.tar`、`g4.tar`，各含 200 张 960×540 的灰度雪花 PNG。

从这一刻开始，解题方向就很明确了：**每条附加轨道/附件都是独立的数据源**，要分别提取。

### 1.1 提取附件

用 MKVToolNix 的 `mkvextract`：

```bash
mkvextract "Secrets of the Cosmic Microwave Background.mkv" attachments
```

会得到 `g2.tar`、`g4.tar`。也可以直接用 ffmpeg 导出附件（流编号按 `ffmpeg -i` 显示为准）：

```bash
ffmpeg -i "Secrets of the Cosmic Microwave Background.mkv" \
       -dump_attachment:4 g2.tar \
       -dump_attachment:5 g4.tar -f null -
```

解开附件：

```bash
tar -xf g2.tar
tar -xf g4.tar
```

得到 `g2/000000.png ... g2/000199.png` 和 `g4/000000.png ... g4/000199.png`。

### 1.2 提取第二条视频轨（雪花流）

```bash
mkdir extra
ffmpeg -i "Secrets of the Cosmic Microwave Background.mkv" \
       -map 0:2 -vsync 0 extra/%04d.png
```

共 400 张 1280×720 的雪花帧。它们其实是**两段各 200 帧的序列**拼在一起（后面会解释）。

### 1.3 提取字幕轨

```bash
ffmpeg -i "Secrets of the Cosmic Microwave Background.mkv" \
       -map 0:3 subs.srt
```

打开 `subs.srt` 会发现：每条字幕的“文本”不是人话，而是一长串十六进制字符，开头是：

```text
89504e470d0a1a0a ...
```

`89 50 4e 47 0d 0a 1a 0a` 正是 PNG 的文件头。也就是说，**字幕流里藏的是 200 张 PNG 的十六进制**。

### 1.4 提取正片结尾的雪花

正片播放到最后，PBS Digital Studios logo 之后还有一段约 8 秒的电视雪花（约从 1030.96 秒开始）。把这段也抽出来：

```bash
mkdir mainstatic
ffmpeg -ss 1029 -i "Secrets of the Cosmic Microwave Background.mkv" \
       -map 0:0 -vsync 0 mainstatic/%04d.png
```

这段雪花里藏着最后一个词，先记住这个位置。

## 2. 核心技巧：雪花里的文字怎么看？

### 2.1 观察

肉眼直接看任意一帧，都是密密麻麻的随机噪点，什么都看不到。把帧放大、调对比度，也还是噪点。

但如果你把**相邻的两帧**放在一起逐像素比较，会发现在某些帧对里，有一片区域的两帧像素值**完全相同**；而其余随机噪声区域，两帧几乎不会完全相同。

为什么？因为作者在生成雪花时，把要隐藏的文字像素“固定”在了成对的帧里：文字区域两帧共用同一份填充值，背景噪声则每帧重新随机。于是：

- 背景随机噪声：两帧同一像素相等的概率很小（8 位灰度约 1/256，二值雪花约 1/2）；
- 文字笔画区域：两帧同一像素几乎必然相等。

对“相邻帧逐像素是否相等”做一张图，再做局部平滑，文字就会浮现。

### 2.2 公式化

设相邻两帧为 `A(x,y)`、`B(x,y)`，定义相等掩码：

```
E(x,y) = 1,  若 A(x,y) == B(x,y)
         0,  否则
```

然后对 `E` 做窗口平滑（例如 9×9 的局部平均）：

```
M(x,y) = (1/|W|) * Σ E(x', y')
```

在随机噪声区域，`M ≈ 0.5`（二值）或很小（8 位）；在文字区域，`M ≈ 1`。把 `M` 拉伸到 0–255 显示，文字就出来了。

> 二值雪花（像素只有 8 和 242 两级）的随机相等率约 0.5，所以文字区域的对比没有 8 位雪花那么夸张，但依然很明显。
>
> 8 位雪花（0–255）的随机相等率约 1/256，文字区域接近 1，因此文字非常醒目。

### 2.3 处理流程

1. 把某一组 PNG 序列转成 raw 灰度视频（方便 Python 读取）：

```bash
ffmpeg -framerate 25 -i extra/%04d.png \
       -vf "scale=960:540:flags=area,format=gray" \
       -f rawvideo extra.raw
```

2. 用下面的脚本逐对计算相等性局部图，只保存“高亮像素很多”的帧对：

```python
# reveal.py
# 用法: python3 reveal.py <raw灰度文件> <输出目录>
# raw 文件要求：每帧 W*H 字节，灰度 8 位
import sys, os

W, H = 960, 540
N = W * H

def load_frames(path):
    d = open(path, 'rb').read()
    assert len(d) % N == 0, "文件大小不是 W*H 的整数倍"
    n = len(d) // N
    return [d[i*N:(i+1)*N] for i in range(n)]

def equality_map(a, b, R=4):
    # 1) 逐像素相等掩码
    eq = bytes(1 if a[k] == b[k] else 0 for k in range(N))

    # 2) 积分图，用于 O(1) 计算局部窗口和
    S = [[0] * (W + 1) for _ in range(H + 1)]
    for y in range(H):
        row = eq[y*W:(y+1)*W]
        Sy, Sy1 = S[y], S[y+1]
        for x in range(W):
            Sy1[x+1] = Sy[x+1] + Sy1[x] - Sy[x] + row[x]

    # 3) 局部平均（窗口 (2R+1)x(2R+1)）
    out = bytearray(N)
    win = (2*R + 1) ** 2
    for y in range(H):
        y0, y1 = max(0, y-R), min(H, y+R+1)
        for x in range(W):
            x0, x1 = max(0, x-R), min(W, x+R+1)
            s = S[y1][x1] - S[y0][x1] - S[y1][x0] + S[y0][x0]
            out[y*W+x] = s * 255 // win
    return out

def main(raw_path, out_dir):
    frames = load_frames(raw_path)
    os.makedirs(out_dir, exist_ok=True)
    for i in range(len(frames) - 1):
        m = equality_map(frames[i], frames[i+1])
        # 高亮像素数量：文字帧对会明显偏多
        hot = sum(1 for v in m if v > 200)
        if hot > 200:
            open(f"{out_dir}/{i:04d}.gray", "wb").write(m)
            print("frame pair", i, i+1, "hot pixels", hot)

if __name__ == "__main__":
    main(sys.argv[1], sys.argv[2])
```

3. 把输出的 `.gray` 转成 PNG 查看：

```bash
for f in out/*.gray; do
  ffmpeg -hide_banner -loglevel error -y \
         -f rawvideo -pix_fmt gray -s 960x540 -i "$f" \
         "${f%.gray}.png"
done
```

4. 也可以把同一组所有文字帧对的 `M` 叠加平均，得到更干净的字形（本 WP 的截图文字就是这样得到的）。

### 2.4 实际结果

用上面的方法处理各数据源，读出：

- 第二条视频轨前半段（第 0–199 帧）：`f1a9{S`
- `g2.tar` 里的 200 张 PNG：`3cr3t_`
- 第二条视频轨后半段（第 200–399 帧）：`0f_cM6_`
- `g4.tar` 里的 200 张 PNG：`h1dd3n_`
- 字幕 hex 解码出的 200 张 PNG：`1n51d3_`
- 正片结尾雪花：`5tr34m}`

## 3. 字幕流：十六进制 → 200 张 PNG

`subs.srt` 的每个字幕块格式是：

```text
序号
00:00:00,000 --> 00:00:05,155
<一长串十六进制>
```

把所有“文本行”按顺序拼起来，就是一张 PNG（实际是 200 张 PNG 首尾相接）的十六进制。脚本：

```python
# decode_srt.py
import re, os

srt = open("subs.srt", encoding="utf-8", errors="replace").read()

# 按空行切分字幕块
blocks = re.split(r"\n\s*\n", srt.strip())

hexstr = ""
for b in blocks:
    lines = b.strip().splitlines()
    # 一个块：第 0 行序号，第 1 行时间轴，其余是文本
    if len(lines) >= 2 and "-->" in lines[1]:
        hexstr += "".join(lines[2:])

data = bytes.fromhex(hexstr)

# 按 PNG 文件头切分（每个文件以 IEND 结束）
sig = b"\x89PNG\r\n\x1a\n"
parts = []
pos = 0
while True:
    i = data.find(sig, pos)
    if i < 0:
        break
    j = data.find(b"IEND", i) + 8
    parts.append(data[i:j])
    pos = j

os.makedirs("sf", exist_ok=True)
for n, p in enumerate(parts):
    open(f"sf/{n:05d}.png", "wb").write(p)

print("PNG 数量:", len(parts))
```

输出 200 张 960×540 灰度 PNG，和 `g2`、`g4` 一样，用第 2 节的帧相等性方法即可读出 `1n51d3_`。

## 4. 正片结尾雪花：最后一块拼图

正片最后（PBS Digital Studios logo 之后）是一段约 201 帧的电视雪花。它同样是“成对帧固定文字”的套路，用第 2 节的 `reveal.py` 处理 `mainstatic` 抽出的 raw 灰度帧，即可得到：

```
5tr34m}
```

也就是 leet 的 `stream}`。这个位置很容易被忽略：因为正片看起来是正常纪录片，很多人抽几帧看到雪花就跳过了。题面里“老式电视机的雪花”“1% 来自宇宙微波背景”其实一直在提示：**结尾那段雪花就是“CMB stream”**，最后一段文字藏在里面。

## 5. 组号与拼接：为什么顺序不是英语语序？

这里是本题最容易做错的地方。

我们手上有五个“雪花数据源”：

- 第二条视频轨前半段（0–199 帧）；
- 第二条视频轨后半段（200–399 帧）；
- `g2.tar`；
- `g4.tar`；
- 字幕 hex 解码出的 200 张 PNG。

附件命名为 **`g2`、`g4`**，这不是随便起的：它是**组号**。也就是说，作者把五个数据源编成了 `g1`–`g5`：

| 组号 | 来源 | 提取方法 | 解出的片段 |
|---|---|---|---|
| g1 | 第二条视频轨前半段（0–199 帧） | 帧相等性 | `f1a9{S` |
| g2 | `g2.tar` 里的 200 张 PNG | 帧相等性 | `3cr3t_` |
| g3 | 第二条视频轨后半段（200–399 帧） | 帧相等性 | `0f_cM6_` |
| g4 | `g4.tar` 里的 200 张 PNG | 帧相等性 | `h1dd3n_` |
| g5 | 字幕 hex 解码出的 200 张 PNG | 帧相等性 | `1n51d3_` |
| 末尾 | 正片结尾雪花 | 帧相等性 | `5tr34m}` |

按 `g1 → g2 → g3 → g4 → g5` 顺序拼接：

```
f1a9{S + 3cr3t_ + 0f_cM6_ + h1dd3n_ + 1n51d3_ + 5tr34m}
= f1a9{S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m}
```

注意：**不是**按英语自然语序 “Secret hidden inside of CMB stream” 去拼，而是按组号拼，得到：

> **Secret of CMB hidden inside stream**
>
> （CMB 的秘密藏在流里）

这也正好呼应题面：真正的秘密“藏在流里”。

### 5.1 从 leet 到平台 flag

- `f1a9` = leet 的 `flag`
- `S3cr3t` = `Secret`
- `0f` = `of`
- `cM6` = `CMB`（6 形似 B）
- `h1dd3n` = `hidden`
- `1n51d3` = `inside`
- `5tr34m` = `stream`

平台要求 `flag{}` 前缀，因此把开头的 `f1a9{` 规范成 `flag{`：

```
flag{S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m}
```

这就是最终答案。

## 6. 一键复现思路（命令清单）

```bash
# 1) 看容器结构
ffmpeg -hide_banner -i challenge.mkv

# 2) 导出附件（任选其一）
mkvextract challenge.mkv attachments
# 或
ffmpeg -i challenge.mkv -dump_attachment:4 g2.tar -dump_attachment:5 g4.tar -f null -

# 3) 导出第二条视频轨（雪花）
mkdir extra
ffmpeg -i challenge.mkv -map 0:2 -vsync 0 extra/%04d.png

# 4) 导出字幕（十六进制 PNG）
ffmpeg -i challenge.mkv -map 0:3 subs.srt
python3 decode_srt.py          # 生成 sf/00000.png ...

# 5) 导出正片结尾雪花
mkdir mainstatic
ffmpeg -ss 1029 -i challenge.mkv -map 0:0 -vsync 0 mainstatic/%04d.png

# 6) 各组 PNG -> raw 灰度
for d in extra g2 g4 sf mainstatic; do
  ffmpeg -framerate 25 -i "$d/%04d.png" \
         -vf "scale=960:540:flags=area,format=gray" \
         -f rawvideo "$d.raw"
done

# 7) 逐组跑帧相等性检测
python3 reveal.py extra.raw out_extra
python3 reveal.py g2.raw out_g2
python3 reveal.py g4.raw out_g4
python3 reveal.py sf.raw out_sf
python3 reveal.py mainstatic.raw out_main

# 8) 把输出的 .gray 转 PNG 查看文字
for d in out_extra out_g2 out_g4 out_sf out_main; do
  for f in "$d"/*.gray; do
    ffmpeg -hide_banner -loglevel error -y \
           -f rawvideo -pix_fmt gray -s 960x540 -i "$f" \
           "${f%.gray}.png"
  done
done
```

> 注意：
>
> - `extra` 是 720p，必须先 `scale=960:540` 再按 960×540 处理；
> - `g2`/`g4`/`sf` 本身就是 960×540；
> - `mainstatic` 抽帧时用了 `-ss 1029`，不同 ffmpeg 版本/关键帧定位可能让起始帧号有几十帧偏差，只要覆盖到 PBS logo 之后那段雪花即可；
> - `reveal.py` 里的 `R`（窗口半径）和 `hot > 200` 阈值可以按实际对比度微调。

# 新手向：这道题到底难在哪？

下面这部分写给完全没做过 CTF 视频隐写、甚至没怎么写过脚本的同学。

## 7.1 本题难点

### 难点一：容器里不止一条“视频”

很多新手拿到 `.mkv` 只会拖进播放器看正片。但这道题的作者在 MKV 里塞了：

- 第二条视频轨（雪花）；
- 一条“字幕”轨，内容其实是十六进制；
- 两个附件（`g2.tar`、`g4.tar`）。

如果不知道 MKV 可以有多条流、可以有附件、可以有“伪字幕”，就会直接错过 80% 的题目内容。

### 难点二：隐写方式反常规

常见视频隐写是：

- 文件尾追加数据（`binwalk`、`foremost`）；
- LSB 最低有效位；
- 音频频谱画字；
- 帧里直接画一张图。

这道题都不是。它是**利用相邻帧的像素相等性**来隐藏文字：

- 文字像素在成对的帧里被固定成同一个值；
- 背景噪声每帧随机变化；
- 所以“相邻帧完全相同的像素”在文字区域会形成字形。

这个思路不查资料很难一下想到，需要自己观察数据、提出假设、写脚本验证。

### 难点三：没有“一键工具”

常规题可以 `zsteg`、`steghide`、`binwalk` 一把梭。但这道题需要：

- 自己抽帧；
- 自己把 PNG 转 raw；
- 自己写逐像素比较；
- 自己做局部窗口平滑/积分图；
- 自己批量输出、查看结果。

它考的是“写小脚本做实验”的能力，而不是记工具命令。

### 难点四：拼接顺序不是自然语序

读出来的字是：

```
f1a9{S  3cr3t_  0f_cM6_  h1dd3n_  1n51d3_  5tr34m}
```

很多人（包括本 WP 的第一版思路）会按英语语序拼成：

```
S3cr3t_h1dd3n_1n51d3_0f_cM6_5tr34m
```

但正确顺序是由附件名 **`g2`、`g4`** 暗示的组号决定的：

```
g1 g2 g3 g4 g5
```

于是得到：

```
S3cr3t_0f_cM6_h1dd3n_1n51d3_5tr34m
```

即 “Secret of CMB hidden inside stream”。这个“组号排序”的提示非常隐蔽：如果没注意附件名，或者没想过 g1/g3/g5 在哪里，就会拼错。

### 难点五：正片结尾的雪花容易漏掉

正片是正常纪录片，很多人抽几帧看到是科普片就放弃了。实际上 PBS logo 之后还有约 8 秒电视雪花，最后一个词 `5tr34m}` 就藏在那里。题面反复提“老式电视机的雪花”“1% 的 CMB”，就是在暗示结尾这段雪花。

### 难点六：线索、leet 与平台前缀的取舍

找到句子后还要判断：

- `f1a9` 是 leet 的 `flag`；
- `S3cr3t`、`h1dd3n`、`1n51d3`、`0f`、`cM6`、`5tr34m` 各对应什么；
- 平台要求 `flag{}` 前缀，所以最终把 `f1a9{` 规范成 `flag{`；
- 顺序要按组号，不是按英语语序。

这几步任何一步判断错，提交都会失败。

## 7.2 涉及的知识点

### （1）MKV / Matroska 容器

MKV 是一个“容器”，不是单一的视频文件。它可以包含：

- 多条视频轨；
- 多条音频轨；
- 字幕轨；
- **附件（Attachment）**；
- 章节、标签、封面等。

本题用到的关键点：

- `ffmpeg -i` 可以列出所有流；
- `-map 0:2` 选择第 2 条流（从 0 开始编号）；
- 附件可以用 `mkvextract attachments` 或 `-dump_attachment` 导出；
- 字幕轨不一定是“字幕”，它的内容可以是任意文本——本题就是十六进制。

### （2）ffmpeg 常用操作

- `-ss`：跳转到指定时间；
- `-map`：选择流；
- `-vsync 0`：按原始帧率输出；
- `-vf scale=...,format=gray`：缩放、转灰度；
- `-f rawvideo`：输出裸像素数据；
- `-pix_fmt gray`：8 位灰度。

这些是视频 misc 题的基本功。

### （3）视频帧、帧率、分辨率

- 帧率（fps）：每秒多少帧；
- 分辨率：每帧多少像素；
- 帧号与时间戳的换算：`时间 = 帧号 / fps`；
- 720p 与 540p 的缩放：本题附加轨是 1280×720，附件/字幕 PNG 是 960×540，处理时要统一尺寸。

### （4）随机噪声与统计

- 随机噪声的相邻像素/相邻帧像素几乎不会完全相同；
- 如果某些像素被作者“固定”，它们的相等性会显著高于背景；
- 对“相等性”做局部平均，就是在做一次简单的统计检测。

这其实就是题面里“天文学家从噪声中提取 1% 微弱信号”的迷你版：单看一个像素分不清，但大量像素/帧统计后，信号就出来了。

### （5）局部窗口统计与积分图

- 直接对每个像素开窗口求和很慢；
- 用积分图（Summed-Area Table）可以把窗口求和降到 O(1)；
- 这是图像处理里非常常用的技巧，也是本题脚本性能的关键。

### （6）PNG、十六进制、SRT

- `89 50 4E 47 0D 0A 1A 0A` 是 PNG 文件头；
- 十六进制文本每两个字符是一个字节；
- SRT 字幕格式：序号、时间轴、文本；
- 把字幕文本拼起来再 `bytes.fromhex`，就能还原二进制文件；
- 按 PNG 的 `IEND` 结束标记可以切分首尾相接的多张 PNG。

### （7）leet speak

leet（黑客语）用数字/符号替代字母，例如：

| leet | 原字母 |
|---|---|
| 1 | i / l |
| 3 | e |
| 4 | a |
| 5 | s |
| 0 | o |
| 6 | b |
| 9 | g |

本题的 `f1a9` 就是 `flag`，`S3cr3t` 是 `Secret`，`5tr34m` 是 `stream`。

### （8）CTF flag 格式

- 平台通常要求 `flag{...}`；
- 题目隐藏的字符串可能是 leet 写法，需要还原或只还原前缀；
- 本题最终提交的是 `flag{...}`，内容保留 leet。

## 7.3 掌握此题需要的技能

1. **工具链熟练度**
   - 会看 `ffmpeg -i` 的输出；
   - 会 `-map` 选流、抽帧、转 raw；
   - 会用 MKVToolNix 或 ffmpeg 导附件。

2. **Python 脚本能力**
   - 读写二进制文件；
   - 批量处理帧；
   - 字节/整数运算；
   - 写循环、函数、文件输出；
   - 会做简单的性能优化（如积分图）。

3. **图像基础**
   - 灰度、像素、分辨率；
   - 局部窗口/滤波；
   - 知道“噪声”和“信号”的区别。

4. **实验设计能力**
   - 先观察：同一帧看不出来，就试相邻帧；
   - 提出假设：文字像素可能在帧间被固定；
   - 设计指标：逐像素相等性；
   - 验证：局部平均后看图。

5. **数据管理**
   - 几百上千帧，命名、帧号、时间戳要清楚；
   - 不同数据源要分开目录；
   - 处理前统一尺寸/格式。

6. **耐心与细心**
   - 组号排序的线索藏在附件名里；
   - 正片结尾的雪花容易漏；
   - leet 的每个字符都要仔细核对。

7. **抗干扰能力**
   - 找到一句通顺的话，不代表就是最终 flag；
   - 要考虑顺序、前缀、leet、平台格式；
   - 失败后要能回头检查假设，而不是盲目猜字符串。

## 7.4 给新手的练习路径

如果你想从零开始补：

1. **misc 基础工具**
   - `file`、`strings`、`binwalk`、`foremost`；
   - 图片隐写基础：LSB、`zsteg`、`stegsolve`；
   - 压缩包伪加密、文件头修复。

2. **视频/音频基础**
   - 用 ffmpeg 抽帧、转码、看流；
   - 用 MKVToolNix 看轨道和附件；
   - 了解帧率、分辨率、YUV、灰度。

3. **写小脚本**
   - 批量读图片、统计像素；
   - 做帧差、帧相等性、局部平均；
   - 把结果保存成图片查看。

4. **做几道“视频抽帧 + 帧间运算”的题**
   - 常见套路：相邻帧 XOR、帧差、平均、找异常帧、找重复帧；
   - 本题是“相邻帧相等性”的一个变种。

5. **养成看“题面暗示”和“附件命名”的习惯**
   - 题面反复提雪花、CMB、1%，说明重点在雪花/结尾；
   - `g2`、`g4` 这种命名，往往就是顺序/分组提示。
