## 一、关系代数（50 分钟）

| 符号 | 名称     | 一句话                           | 例子                         |
| ---- | -------- | -------------------------------- | ---------------------------- |
| σ    | 选择     | **挑行**，条件写在右下角         | σ salary>5000 (employee)     |
| π    | 投影     | **挑列**，自动去重               | π emp_name,salary (employee) |
| ×    | 笛卡尔积 | 两表所有组合                     | employee × sales             |
| ∪    | 并       | 合并去重，**两边结构要一样**     | A ∪ B                        |
| −    | 差       | 左边有、右边没有，**结构要一样** | A − B                        |
| ∩    | 交       | 两边都有（导出）                 | A ∩ B                        |
| ⋈    | 连接     | 按条件拼行（导出）               | A ⋈ A.x=B.y B                |
| ÷    | 除       | "至少包含全部"（导出）           | R ÷ S                        |

必背：**5 种基本运算是 σ、π、×、∪、−**；∩、⋈、÷ 是导出运算。单选题常考这一条。

四条铁律：

1. π 和 σ 是"外衣"，先决定给的是行集还是列集：题里问"…的某属性"外面套 π，问"满足…的"套 σ。
2. 差、并、交要求两边**属性个数、类型、含义一致**，所以先各自 π 到同结构。
3. 连接要先写条件，不写条件就是笛卡尔积。
4. 除法只用于"全部/所有/至少包含"这类词。

题面说法 → 骨架：

| 题面                  | 关系代数骨架                                 |
| --------------------- | -------------------------------------------- |
| …的员工姓名和工资     | π 属性 (σ 条件 (表))                         |
| 既…又…                | π A (R) ∩ π A (S)                            |
| 没有购买…的           | π 名 (customer) − π 名 (σ 条件 (子查询联结)) |
| 某部门员工销售的订单… | π … (σ 条件 (表) ⋈ 条件 表 ⋈ 条件 表)        |
| 至少包含某订单的全部  | π A,B (R) ÷ π B (σ 条件 (R))                 |

拿你昨天那 5 题当模板抄三遍（这 5 个覆盖 90% 可能考法）：

```text
-- 1、工资超过5000的员工的姓名及工资
1. π emp_name,salary ( σ salary>5000 (employee) )

-- 2、既购买20652又购买22082的订单
2. π order_no (σ book_no='20652'(sale_item)) ∩ π order_no (σ book_no='22082'(sale_item))

-- 3、没有购买20652号图书的顾客姓
3. π cust_name (customer) − π cust_name (σ book_no='20652'(sale_item ⋈ sales))

-- 4、业务部员工所销售每笔订单的订单号、图书编号、图书名及数量
4. π order_no,book_no,book_name,qty ( σ dept='业务'(employee) ⋈ emp_no=sale_id sales
                                      ⋈ order_no sale_item ⋈ book_no books )

-- 5、购买的图书至少包含102893订单所购图书的订单号（除法）
5. π order_no,book_no(sale_item) ÷ π book_no(σ order_no='102893'(sale_item))
```

三个致命错误：差集两边结构不同（先 π）、连接漏条件（变笛卡尔积）、除法分子忘了投影出"订单+书"两列。

## 二、理论（35 分钟，7 张卡）

**卡1 四个概念**：数据（描述事物的符号记录）；数据库（长期存储、有组织、可共享的数据集合）；DBMS（管理数据库的软件：定义、操纵、运行管理、维护）；DBS（数据库+DBMS+应用+DBA+用户）。

**卡2 三级模式与两级映射**：外模式（用户视图，多个）→ 模式（全局逻辑，一个）→ 内模式（物理存储，一个）。外模式/模式映像保**逻辑独立性**；模式/内模式映像保**物理独立性**。

**卡3 数据模型三要素**：数据结构、数据操作、完整性约束。常用模型：层次、网状、关系（了解级，选择题出现就认名字）。

**卡4 概念模型**：实体、属性、码、实体型、实体集、联系（1:1、1:n、m:n）。最常用 E-R 图。

**卡5 关系与性质**：域→笛卡尔积→关系（笛卡尔积的子集）。性质：元组次序无关、列次序无关、不能有重复元组、属性不可再分。

**卡6 完整性**：实体完整性=主码唯一且非空；参照完整性=外码取空值或等于被参照表的某个主码值；用户定义完整性=具体业务规则（如成绩 0–100）。

**卡7 索引与视图**：索引加快查询，本质是排序结构（B+树），代价是占空间、拖慢增删改；`CREATE INDEX` / `DROP INDEX`。视图作用=简化查询、逻辑独立性、安全控制；含聚合、GROUP BY、DISTINCT 的视图**不可更新**。

多选题策略：漏选得 1 分、错选 0 分——**只选自己确定的**，拿不准的一律不选。

## 三、SQL 操作题（40 分钟，9 题）

大概率就这 9 类，每类手写一遍：

```sql
-- 建表（主键+外键）
CREATE TABLE t(
  id CHAR(5) PRIMARY KEY,
  name VARCHAR(20) NOT NULL UNIQUE,
  cid CHAR(5),
  FOREIGN KEY (cid) REFERENCES c(id)
);

-- 索引
CREATE [UNIQUE] INDEX idx_name ON t(name);
DROP INDEX idx_name ON t;

-- 单表/多表/外连接
SELECT ... FROM a JOIN b ON a.x=b.y WHERE ...;
SELECT ... FROM a LEFT JOIN b ON ... WHERE b.x IS NULL;

-- 嵌套（IN / EXISTS / NOT EXISTS）
SELECT ... WHERE x IN (SELECT x FROM ...);
SELECT ... WHERE NOT EXISTS (SELECT 1 FROM ... WHERE ...);

-- 分组
SELECT ... FROM ... GROUP BY ... HAVING COUNT(*)>1;

-- 集合（UNION 去重 / UNION ALL 不去重）
SELECT ... UNION SELECT ...;

-- 派生表
SELECT * FROM (SELECT ... ) t WHERE ...;

-- 增删改
INSERT INTO t(列) VALUES(...);
UPDATE t SET 列=值 WHERE ...;
DELETE FROM t WHERE ...;

-- 视图
CREATE VIEW v AS SELECT ... [WITH CHECK OPTION];
```

三个最可能丢分的点：`NOT IN` 子查询里有 NULL 会整体失效（用 `NOT EXISTS`）；聚合条件写进 `HAVING` 不是 `WHERE`；`CREATE VIEW` 后问能不能改，答"含聚合/GROUP BY 的不可更新"。

## 四、分析题（30 分钟，12 分）

固定三段式，题目问哪一种就写哪一段：

**功能**：一句话——"在 X 表中筛选满足 Y 的行，输出 Z 列"，或"把 X 表的某列更新为…，条件是…"。

**执行过程**：`FROM/JOIN 生成候选行 → WHERE 逐行判断 → GROUP BY/HAVING → SELECT 计算输出列 → ORDER BY`。遇到子查询补一句：不相关子查询"先执行一次，结果作为条件"；相关子查询"外层每取一行，代入内层执行一次，存在/不存在决定取舍"。

**问题**：点名缺陷 + 后果 + 改法。高频就这 6 个：

| 问题                     | 后果                                           |
| ------------------------ | ---------------------------------------------- |
| 内连接查"没有…的"        | 无记录的行直接消失 → 改 NOT EXISTS / LEFT JOIN |
| NOT IN + NULL            | 结果整体为空 → 改 NOT EXISTS                   |
| WHERE 里用聚合/列别名    | 报错 → 改 HAVING / 重写表达式                  |
| 聚合视图 UPDATE          | 1288，不可更新                                 |
| 删父表还有子记录         | 1451，先删子表或级联                           |
| UPDATE/DELETE 忘写 WHERE | 全表被改，最严重                               |

## 五、只重做这 8 题（20 分钟）

1. 同一订单包含 102893 全部图书（双重 NOT EXISTS）——对应除法 ÷
2. 没买 20652 的顾客（差集）——对应 −
3. 既买 20652 又买 22082（交集）——对应 ∩
4. 业务部员工的订单链（多表连接）——对应 ⋈
5. 学习课程与 01 完全相同的同学（双向 NOT EXISTS）
6. 平均分 <60、无成绩算 0.00（LEFT JOIN + COALESCE + CAST）
7. 两门及以上不及格（CASE WHEN + HAVING）
8. 视图 WITH CHECK OPTION 插入失败 + 聚合视图改不动（分析题模板）
