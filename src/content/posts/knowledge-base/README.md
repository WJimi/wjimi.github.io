# 知识库（精简版草稿）

这里不是笔记本，是**问题驱动的问题图谱**：从真实目标出发，在解决问题里长知识，不背书、不刷课。

## 一分钟上手

打开这个库，只回答一句："我现在要解决什么？"

目标 -> 问题 -> 动手 -> 交付物 -> 一句话沉淀 -> 新问题 -> 回到目标

1. 有目标（如 [[Web 安全 8 周目标]]）—— 拆成下一个问题。
2. 有问题 —— 在 `01_questions` 找到它，动手；没有就先建一篇。
3. 动手 —— 产出能跑的脚本，或一篇写清机制的笔记。
4. 收尾 —— 回答四问：解决了什么 / 真正理解了什么 / 产生什么新问题 / 下一步最重要的问题。
5. 新问题 —— 进 `00_inbox`，或挂到某篇的 `## 待答问题` 下。

没目标就先找目标。目标可以改路线，路线不能限制目标。

## 什么是好问题（三条测试）

能不能执行，不取决于问题偏理论还是偏实践，取决于这三条：

1. **锚点测试**：正文 `## 为什么现在出现` 点名一个真实目标或卡点。"一直想知道 X"不是锚点，"做 Y 时卡在 X"才是。
2. **下一步测试**：`## 待答问题` 至少有一条，能写成 15 分钟动手的任务。只有"理解一下、梳理一下"的不算。
3. **第一人称测试**：是我自己的问题（我卡在 X），不是"关于 X 的提炼"。为会话做总结产生的问题通常过不了这条。

通不过的分流：

- 有锚点、没下一步 —— 补一条能动手的 `## 待答问题`。
- 没锚点、纯好奇 —— 降级到 `04_explore`，别占着问题队列。
- 其实是概念不是问题 —— 并进 `02_kownledge`。
- 三条都过不了、也没归属 —— 删，别留着假装在学。

## 目录（真实结构，不是理想结构）

```
knowledge-base/
├─ 00_inbox     收件箱：新问题先丢这，未归类
├─ 01_questions 问题：每篇一个问题，正文有 ## 状态 和 ## 待答问题
├─ 02_kownledge 知识：机制写清楚，一个概念一篇（目录名拼写是历史遗留，别改）
├─ 03_projects  项目：一个真实项目一篇，是问题的发动机
├─ 04_explore   待探索：有价值但当下不必要
└─ review       复盘：做题记录、比赛 WP、方法论
```

`src/content` 下还有 `dynamic`、`spec`、`guide`、`romp` 等其他内容，不属于这个知识图谱，不混进来。

## 问题状态（用词）

写在正文 `## 状态` 段第一句，用你已经在用的词：

- `当前` / `前置` / `新问题` —— 正在被解决的
- `部分解决` / `待继续` —— 有进度但没完
- `已解决` —— 能解释、能使用、能排错
- `已定目标` —— 问题已经转化成项目
- `反复出现` —— 行为模式问题，不是知识缺口，优先处理

状态是复盘时顺手写的，不是每次打开先维护的字段。没有 `## 待答问题` 的问题，状态写什么都执行不起来。

## 一篇问题笔记长什么样

```markdown
# 问题本身（问句结尾）

## 状态
当前

## 为什么现在出现
哪个目标、哪个项目把这个问题挤出来的。

## 它依赖什么
最小前置，别为了一个问题把整个领域学完。

## 它连接什么
- [[相关笔记]] —— 一句关系

## 待答问题
- 具体到能立刻动手验证的一句

## 事实
只写验证过的。AI 说的不算，跑通的才算。

## 结论
写不出就空着，别凑。
```

知识类（`02_kownledge`）用：`## 来源` / `## 它解决的问题` / `## 当前理解` / `## 相关问题` / `## 实践`。

## 收件箱规则（防止暂存区变仓库）

`00_inbox` 是暂存，不是家：

- 新问题进来先问三件事：它来自哪个目标、依赖什么、现在必须解决吗。
- 必须解决的搬到 `01_questions`；有价值但不急的进 `04_explore`；只是想法就并进已有笔记。
- 一周至少清一次，在途不超过 5 篇，超过就归档或删。

## 目标与项目

任何时候只维持一个主焦点：**当前目标 > 当前问题 > 知识**。

项目（`03_projects`）负责制造问题。不同项目会经过同一批基础知识，那些重复出现的节点才是真正重要的基础设施。

## 遇到新概念

先问四句：它解决什么问题 / 为什么需要它 / 输入输出是什么 / 和我已有的什么有关。
不要先问"它怎么背"。

掌握的最低标准是"解释 + 识别 + 使用 + 排错"，最高是能重新推导，不是记住答案。

## AI（agent）的角色与边界

现在的 AI 不是聊天框：它会读文件、写文件、跑命令、带技能。所以边界要写死：

- 它负责：拆解问题、写能跑的代码、查资料、草拟笔记、提醒知识缺口、帮你把模糊的困惑重构成好问题。
- 它不负责：替你判断"学会了没有"、替你发布、替你决定学什么。
- 草拟的笔记一律 `draft: true`，你复核、你复述、你发布。
- AI 给的答案不等于你掌握的知识。结论必须是你自己能复述的东西。

## 三条底线

1. 问题驱动知识，不是知识驱动问题。
2. 只补当前真正需要的最小缺口。
3. 重要不等于现在必须学。

防工具崇拜、防收藏家谬误、防"学完"幻觉——都是这三条推出来的，不再单独列。
