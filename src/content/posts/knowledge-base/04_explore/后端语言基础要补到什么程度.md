# 后端语言基础要补到什么程度

## 来源

定下 [[Web 安全 8 周目标]] 之后的第一反应是
"Python、Linux、PHP/Java 都不够扎实"。这条笔记把"扎实"这个模糊的标准换成能当场测的东西。

## 它解决的问题

基础不扎实，要不要先补完再做题？补到什么程度算够？

## 当前理解

安全里需要的是**三种读写代码的能力**，不是"掌握一门语言"：

| 要做的事 | 对应语言 | 够用的标准 |
| --- | --- | --- |
| 写工具、脚本、自动化 | Python | 50 行以内能写清一个脚本：读文件、发 HTTP 请求、处理文本；能读懂一个开源小工具的目录结构 |
| 读懂别人的代码（审计、分析漏洞） | PHP | 能追一个 `index.php` 里参数从 `GET` 到 SQL 的流转，能指出哪一行把输入直接拼进了语句 |
| 改得动别人的代码（复现、写 PoC） | PHP / Java | 能改开源项目的几行让它跑起来，能看懂一个 Servlet 的请求入口 |
| 环境 | Linux | 起服务、看日志、改权限、定位端口占用 |

**Java 放最后**：企业级漏洞（反序列化、组件）才需要它，入门阶段用不到。

已有的证据（别把自己当零基础）：buff-trade 是多文件 Python 管线（`run_pipeline.py` / `shell.py` /
`recipe_ids.py`），strmatcher 是带 git 的 C++ 项目，IVN 那道题自己写了 PHP + SQLite 的建库和注入点。
缺的更像不是"会不会写"，而是"读别人的代码慢"。

## 领域地图：机制 × 语言

（2026-10-12 补充）做题时收出来的一层：**漏洞和语言的"特性"有关，不是和语言本身有关。**
"把用户数据当代码执行"只有那么几种机制，各语言只是在同一批机制里填不同的名字。
按语言列清单会得到几张互不相干的表，换门语言就归零；按机制列才可迁移。

| 数据被当成代码的机制        | PHP                                        | Python                       | Java                               | JS / Node           |
| ----------------- | ------------------------------------------ | ---------------------------- | ---------------------------------- | ------------------- |
| 显式求值              | `eval` / `assert(字符串)` / `preg_replace /e` | `eval` / `exec`              | SpEL / OGNL / Nashorn              | `eval` / `Function` |
| 动态调用（名字可控）        | 变量函数 `$f()`、可变变量 `$$x`、`call_user_func`    | `getattr` / `globals()[...]` | 反射                                 | `obj[name]()`       |
| 反序列化（还原对象时触发魔术方法） | `unserialize` → `__wakeup` / `__destruct`  | `pickle` → `__reduce__`      | `ObjectInputStream` → `readObject` | 原型链污染               |
| 模板 / 表达式          | Twig / Smarty                              | Jinja2                       | FreeMarker / Velocity              | EJS / handlebars    |
| 拼进另一个解释器          | `system` / `include`                       | `os.system` / `subprocess`   | `Runtime.exec`                     | `child_process`     |

用法是**定位**，不是学习顺序：先判断卡在哪一格，只补那一格；能跨语言迁移同一格才算熟练
（Jinja 的 SSTI 和 PHP 的 `eval` 同在"显式求值"这一行）。

**还有第四种能力。** 上面那三种读写能力的表全是"读代码"，但决定成败的常常是不在里面的一项——
**认语言怪癖**，也就是那些不成体系、却常被当技巧用的边缘行为：PHP 7 未定义常量回退成字符串
（[[PHP 7 未定义常量为什么会变成字符串]]）、弱类型比较、`0e` 开头的哈希、Python 的
`__globals__` 可达图、JS 的原型链。这一项读语法书读不到，只能一条一条攒。

## 实践

**现在不补**，理由是纲要第 7 节：只补当前目标需要的最小缺口——8 周主线是 PortSwigger，
大多数 lab 是单点漏洞，不需要读大段后端代码。

触发条件写清楚，卡住就当场补，不做前置学习：

- 做 lab 时**读不懂它给的 PHP/JS 片段** → 当场补用到的那几个语法点，不是从头学 PHP；
- 想复现的 CVE 是个 PHP/Java 项目 → 从那个项目的入口文件开始读；
- 想写脚本却卡住 → 补 Python，库里已有 [[读懂 Python 脚本需要的语法点]]。
