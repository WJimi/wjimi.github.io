# 标品和非标品差在哪

## 来源

问「什么是标品」时产生，背景是 [[knowledge-base/03_projects/automation/tradeup-material-sourcing|CS2 炼金配方的自动取材]]。

## 它解决的问题

BUFF 把自己平台上的东西分成标品和非标品，这条线直接决定了自动化能怎么做——
所以得先知道它按什么切。

## 当前理解

分界线不是「便宜/贵」也不是「常见/稀有」，是：
**同一个 `goods_id` 下面的一堆在售，要不要挑具体是哪一件。**

| | 同一 goods_id 下的实例 | 下单时你要说什么 | 有哪些 |
| --- | --- | --- | --- |
| 标品 | 交易上完全等价，买哪个都一样 | 「买 3 个，单价不超过 X」 | 印花、武器箱、音乐盒、工具、涂鸦、通行证、收藏品、布章、礼物 |
| 非标品 | 每一件都不一样 | 「我要这一件」（报订单号） | 枪、刀、手套 |

为什么会有这条线：CS2 的物品自带随机属性（磨损、图案模板、印花）。
一旦这些属性成了物品身份的一部分，交易就不再是「买一个商品」，而是「买一个具体对象」。
所以这条线是**接口设计层面**的，不是营销说法——标品能批量下单，非标品只能一笔一笔买。

一条能被验证的推论：**磨损（`paintwear`）只属于非标品。**
接口文档里 `asset_info.paintwear` 的说明直接写着「磨损值，仅武器类型返回」；
武器箱、通行证这类标品根本没有这个字段。
所以「我要按磨损筛」这句话本身，就已经把范围限定在非标品里了。

## 实践

2026-09-27：把接口文档里的两档服务和「筛 / 买」交叉起来看，才发现这条线的真正后果——
**筛和买可以分别落在不同的付费档上**：

| | 开发者 API ¥300 | 企业 API ¥1000 |
| --- | --- | --- |
| 筛到「档」：固定磨损区间的最低价、在售数量、流通性 | ✅（每日最多 200 个不同饰品） | ✅ |
| 筛到「件」：每一件确切的 `paintwear`、图案、印花 | ❌ | ✅ 只有「指定饰品在售订单列表」返回 |
| 买「件」：指定订单号直接买走 | ❌ | ✅ 限在售最低价 3000 元以下的枪类 |
| 挂买单：求购，可带磨损区间，等别人卖给我 | ✅ | ✅ |
