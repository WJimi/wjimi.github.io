三个工具对比及 dirsearch 安装与使用教程

# 一、三个工具的用途 & 局限性对比（CTF/Web 渗透视角）

我把三个工具的核心定位、适用场景、优缺点给你拆得明明白白，方便你在不同阶段选对工具👇

## 1. `ds_store_exp`

### ✅ 核心用途

专门利用 **macOS 系统自动生成的** **`.DS_Store`** **文件泄露漏洞**：

- `.DS_Store` 会记录文件夹内的**所有文件名、目录结构、文件属性**，如果网站把这个文件暴露在公网，工具会自动解析、递归爬取目录，甚至直接下载所有可访问的文件。
- 典型场景：CTF 中 `.DS_Store` 泄露题型、渗透测试中发现目标站存在 `.DS_Store` 时，一键扒出完整目录树，挖到后台、备份、源码等敏感内容。

### ❌ 局限性

- **依赖前提极强**：必须目标网站**存在且可访问** **`.DS_Store`** **文件**，否则完全失效；
- **仅针对 macOS 环境**：Linux/Windows 服务器不会生成 `.DS_Store`，对这类目标无效；
- **无法主动发现泄露**：只能在你已经知道 `.DS_Store` 存在时使用，不能主动扫描找漏洞；
- **递归深度有限**：深层嵌套目录可能漏扫，需要手动补全。

## 2. `dvcs-ripper`

### ✅ 核心用途

专门利用 **版本控制系统（VCS）目录泄露漏洞**，支持 Git/SVN/Mercurial/Bazaar 四种主流版本库：

- 当网站意外暴露 `.git/`、`.svn/` 等版本库目录时，工具会远程下载元数据，**完整重建整个代码仓库**，直接拿到网站源码、历史提交记录、数据库配置、密码等所有敏感信息。
- 典型场景：CTF 中 Git/SVN 源码泄露题型、渗透测试中发现版本库目录泄露，是这类题的「标配工具」。

### ❌ 局限性

- **依赖前提极强**：必须目标网站**可访问版本库核心文件**（如 `.git/HEAD`、`.svn/wc.db`），否则无法运行；
- **仅针对版本库泄露**：对非版本控制的普通目录 / 文件完全无效；
- **无法主动发现泄露**：只能在你已经知道版本库目录存在时使用，不能主动扫描；
- **Git 大仓库效率低**：大型项目的 `.git` 目录爬取耗时久，容易被服务器拦截。

## 3. `dirsearch`

### ✅ 核心用途

**通用型 Web 目录 / 文件扫描工具**（CTF/Web 渗透「信息收集阶段」的核心工具）：

- 基于字典 + 多线程，主动枚举目标网站的**隐藏目录、备份文件、敏感文件**（如 `.swp`、`.bak`、`admin/`、`phpinfo.php` 等），帮你找到潜在的注入点、后台入口、源码泄露点。
- 典型场景：渗透测试前期全量目录扫描、CTF 中找隐藏路径、配合其他工具定位漏洞入口。

### ❌ 局限性

- **依赖字典质量**：扫描结果完全取决于字典，字典里没有的路径 / 文件绝对扫不出来；
- **无法主动利用漏洞**：只能「发现路径」，不能像 `ds_store_exp`/`dvcs-ripper` 那样自动解析 / 下载源码；
- **容易被 WAF 拦截**：高并发扫描会触发防火墙，导致被封 IP、扫描中断；
- **误报率较高**：部分 403/404 页面会被误判为 200，需要人工验证；
- **不支持递归解析**：扫到 `.DS_Store`/`.git` 后，不会自动解析目录，需要手动用对应工具处理。

## 🔍 三者核心差异总结表

| 工具           | 核心定位                 | 主动 / 被动            | 依赖前提                            | 核心优势                                 | 核心劣势                         |
| -------------- | ------------------------ | ---------------------- | ----------------------------------- | ---------------------------------------- | -------------------------------- |
| `ds_store_exp` | `.DS_Store` 泄露专用工具 | 被动（需已知漏洞存在） | 目标存在可访问的 `.DS_Store`        | 一键解析目录 + 下载文件，针对 macOS 泄露 | 适用场景极窄，无漏洞则完全失效   |
| `dvcs-ripper`  | 版本库泄露专用工具       | 被动（需已知漏洞存在） | 目标存在可访问的 `.git`/`.svn` 目录 | 完整重建源码仓库，拿到历史提交           | 适用场景极窄，仅针对版本库泄露   |
| `dirsearch`    | 通用目录扫描工具         | 主动（主动枚举）       | 仅需目标 URL，无额外前提            | 全场景覆盖，找所有隐藏路径 / 文件        | 依赖字典，无法利用漏洞，易被拦截 |

# 二、dirsearch 下载安装 + 扫描并下载 `.swp` 文件 完整教程

`.swp` 是 **vim 编辑器的临时交换文件**，如果网站暴露了 `.swp`，可以直接下载后恢复出完整源码，是 CTF 高频考点。

## 1. dirsearch 下载安装（Kali 直接上手）

### 方法 1：Git 克隆（推荐，最新版）

```bash
# 进入你之前的 Tools 目录，统一管理工具
cd ~/Tools
# 克隆官方仓库（--depth 1 只拉取最新版，速度更快）
git clone https://github.com/maurosoria/dirsearch.git --depth 1
# 进入工具目录
cd dirsearch
# 安装依赖（Kali 默认带Python3，直接用pip3）
pip3 install -r requirements.txt
```

### 方法 2：直接下载 ZIP 包（适合网络不好的情况）

- 官方地址：https://github.com/maurosoria/dirsearch/archive/refs/heads/master.zip
- 下载后解压到 `~/Tools/dirsearch`，再执行上面的依赖安装命令即可。

## 2. 用 dirsearch 扫描 `.swp` 文件

### 核心命令（CTF 靶场 / 渗透测试通用）

```bash
# 基础扫描：指定目标URL，专门扫.swp文件
python3 dirsearch.py -u http://目标网站/ -e swp -i 200

# 进阶：全量扫描+过滤.swp，避免漏扫
python3 dirsearch.py -u http://目标网站/ -w /usr/share/wordlists/dirb/common.txt -e swp,bak,zip,rar -i 200
```

### 参数说明（新手必懂）

- `-u`：指定目标网站 URL（必填）
- `-e swp`：只扫描后缀为 `.swp` 的文件，大幅提升效率
- `-i 200`：只显示状态码为 200 的结果（过滤 404/403，只保留可访问的文件）
- `-w 字典路径`：指定自定义字典（Kali 自带 `dirb` 字典，适合新手）
- `-t 线程数`：设置扫描线程（默认 20，可根据服务器调整，避免被封）

### 扫描结果说明

扫描完成后，会输出所有可访问的 `.swp` 文件路径，例如：

```Plain
[20:00:00] 200 -  12KB - http://目标网站/index.php.swp
[20:00:01] 200 -   8KB - http://目标网站/admin/login.php.swp
```

这两个就是你可以下载的目标文件。

## 3. 下载扫描到的 `.swp` 文件（3 种方法，新手友好）

dirsearch **只负责扫描路径，不负责下载文件**，需要用以下方法下载：

### 方法 1：手动浏览器下载（最简单，适合单个文件）

直接把扫描到的 `.swp` 完整 URL 复制到浏览器地址栏，回车即可下载到本地。

### 方法 2：`wget`/`curl` 命令行下载（适合批量 / 单个文件）

```bash
# 单个文件下载（wget）
wget http://目标网站/index.php.swp

# 单个文件下载（curl，保存为指定文件名）
curl http://目标网站/index.php.swp -o index.php.swp

# 批量下载：把所有.swp路径存到url.txt，一行一个，然后批量下载
wget -i url.txt
```

### 方法 3：Python 脚本批量下载（适合大量文件）

如果扫描到很多 `.swp`，用脚本自动下载，避免手动操作：

```python
import requests

# 把扫描到的.swp URL放到列表里
urls = [
    "http://目标网站/index.php.swp",
    "http://目标网站/admin/login.php.swp"
]

for url in urls:
    # 提取文件名（最后一个/后面的内容）
    filename = url.split("/")[-1]
    try:
        res = requests.get(url, timeout=10)
        res.raise_for_status()
        with open(filename, "wb") as f:
            f.write(res.content)
        print(f"[+] 下载成功：{filename}")
    except Exception as e:
        print(f"[-] 下载失败：{url}，错误：{e}")
```

保存为 `download_swp.py`，直接运行：`python3 download_swp.py`

## 4. 从 `.swp` 恢复源码（关键步骤）

下载 `.swp` 后，用 vim 命令恢复出完整的源文件：

```bash
# 恢复index.php.swp为index.php
vim -r index.php.swp
# 进入vim后，按:wq保存退出，就会生成完整的index.php源码
```

如果提示「交换文件已存在」，直接按 `R` 恢复即可。

# 三、和你学的 SQL 注入的联动用法

这三个工具完美配合 SQL 注入，形成完整渗透链路：

1. **第一步：dirsearch 全量扫描**：扫出所有隐藏目录、`.swp`/`.DS_Store`/`.git` 等泄露点，找到带参数的动态页面（如 `news.php?id=1`），定位潜在 SQL 注入点；
2. **第二步：用对应工具扒源码**：扫到 `.DS_Store` 用 `ds_store_exp`，扫到 `.git` 用 `dvcs-ripper`，扫到 `.swp` 直接下载恢复，拿到网站源码、数据库表结构、连接信息；
3. **第三步：SQL 注入提权**：用源码里的表结构、字段名，快速构造 SQL 注入 payload，拿到管理员账号密码，甚至 getshell；
4. **第四步：蚁剑连接控制**：注入成功后，用蚁剑连接 webshell，完成整个渗透流程。

# 四、新手避坑小贴士

1. **合规提醒**：所有工具仅可用于**授权测试 / CTF 靶场**，未经允许扫描公网网站属于违法行为，务必遵守法律法规；
2. **dirsearch 字典优化**：CTF 推荐用 `dirb/common.txt`，渗透测试可以用更大的字典（如 `raft-large-directories.txt`），但要注意线程不要太高，避免被 WAF 拦截；
3. **.swp 常见路径**：除了根目录，还要重点扫 `admin/`、`include/`、`config/` 等目录，这些地方的 `.swp` 更容易泄露敏感信息；
4. **工具搭配**：不要用 `ds_store_exp`/`dvcs-ripper` 替代 dirsearch，前者是「漏洞利用工具」，后者是「漏洞发现工具」，两者配合使用效果最佳。
