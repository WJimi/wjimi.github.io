# 桌面端与 WSL 的分工：哪些该共享、怎么共享

## 来源

从 [[我该往哪个方向走]] 收束出 [[Web 安全 8 周目标]] 之后冒出来的工程问题：一台机器上有两套 Codex（Windows 桌面端、WSL 里的 CLI 与 VS Code 插件），它们各读自己的 `CODEX_HOME`，于是"该共享什么"必须显式决定，不能靠默认。

## 它解决的问题

两套环境都当成"随便用"时会出现三种坏账：同一条历史在两端都找不到；同一个文件被两边同时改；改了配置不知道哪一边生效（桌面端读 `C:\Users\wjimi\.codex`，WSL 读 `/home/wjimi/.codex`）。

## 当前理解

### 分工判据：看瓶颈是人还是命令循环

- 要反复试、要起环境、要改文件的活 → WSL/VS Code：打靶场、写 PoC、起 Spring Boot 连数据库、git 提交、把解法固化成能一键复现的脚本。
- 要跑很久、产出给人看、需要逐条审的活 → 桌面端：把零散记录收成一篇 WP、代码审计、批量扫笔记的链接与 frontmatter、写笔记并直接看 Markdown 渲染。

判据不是"哪个更强"，而是这件事卡在命令循环还是卡在人的审阅。

### 会话记录不能同步，也不该同步

会话在本机是 `sessions/*.jsonl`（rollout）加上一个 SQLite 状态库当索引，于是：

- 整个 `.codex` 不能同步：SQLite 的 `-wal`/`-shm` 和写锁在两个进程下会互相破坏；里面还有平台专属的运行时（Linux musl 与 Windows 二进制各一份）、插件缓存、沙箱与临时状态。
- 只拷 rollout 文件也不够：列表索引在状态库里，而且每条记录里记的 `cwd` 是绝对路径 —— Windows 侧记成 `C:\Users\wjimi`，搬到 WSL 后想恢复得换 `--cd`。
- 产品层面没有"实时同步会话"这个能力。要真的只有一个历史，唯一办法是让 agent 只在一侧跑（桌面端把 agent 切成 WSL）。

### 真正该共享的是"单源文件"，不是"同步"

判据：**一份文件，两个环境都直接读**，就不存在同步问题；两处各存一份，就一定会分叉。

- 项目与知识库放在 `C:\...`（WSL 侧看到的是 `/mnt/c/...`）：同一份文件，天然实时。
- `AGENTS.md` 放在仓库里：Codex 每次启动都读，约定改完对两端同时生效 —— 这是唯一能"实时共享规则"的机制。
- `skills/`、`rules/` 挂在各自的 Codex home 下，默认不共享；要实时只能做成软链单源（实测后决定不这么做，见下面「分开用，不盲目同步」）。
- 用量与费用天然共享：两边用同一把 API key。
- 不碰：`*.sqlite*`、`auth.json`、`packages/`、`plugins/` 缓存、沙箱与临时状态。

### 跨端交接靠文件，不靠聊天记录

会话不共享，接手的一侧看不到另一侧说过什么。交接物就是一张几十字的卡片：当前问题、现在到哪、卡在哪、下一步，放 `00_inbox/` 或项目目录里，谁接手谁先读。副作用是逼着自己把问题写清楚。

### 同一时刻只让一侧写同一个项目

两边同时改同一批文件，轻则 git 冲突，重则互相覆盖。桌面端跑长任务时，WSL 侧去做别的项目。

### skill 的两份副本：分开用，不盲目同步（2026-10-09）

`learning-system` 在两侧各一份，印证了上面的判据：没几天就长成两条分支 —— WSL 侧改了链接写法和笔记归属规则，Windows 侧改了平台自适应（Windows/WSL 双路径、`FIREFLY_KB` / `FIREFLY_POSTS`、PowerShell 写法、控制台 UTF-8）和"什么时候用"的界定。两边的改动都是有效的，**直接覆盖会丢掉另一边的工作**。

定下来的做法：**软链弃掉，两侧的 skill 分开使用、各自维护，不做整目录同步。** 两侧的 Codex 版本和常做的任务本来就不同（`.system` 下有 45 个文件不一致），拉平等于把"某一边用不上"的东西也带过去。

真要移植某处改动时：先 `diff -r` 看清两边各自改了什么，只搬需要的那部分，并说明搬了什么、留下了什么。

❓ 哪些改动属于"跟环境无关、该移植"（比如链接规则、笔记归属规则），哪些属于"跟平台绑定、各改各的"（比如路径定位、控制台编码）？这条线还没画。

## 实践

- 两侧各跑一次官方脚本，结果 `models.json` 字节级一致（md5 相同），说明模型元数据没分叉。
- 实测两边的 API key 是同一把（比对哈希而不是比对明文），所以用量只有一份账。
- 发现 `model_reasoning_effort` 两边不一致（WSL 低、Windows 高），同一个任务表现会不同 —— 这类看不见的分叉才是双环境真正的成本。
- 把 WSL 的 `skills/ctf-sqli`、`skills/learning-system` 和 `rules/default.rules` 复制到 Windows 侧的 `.codex`，并把知识库约定写进 Firefly 仓库根的 `AGENTS.md`。
