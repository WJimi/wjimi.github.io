# Web 安全的边界在哪

## 来源

反复问「Web 安全到底包含什么、边界在哪」，一直没得到一个能落地的答案。

## 它解决的问题

这个领域到底按什么切？边界是不是"会哪些工具"？

## 当前理解

按**数据从不可信变可信的每一次跨越**切。

浏览器发来的每个字节都是敌意输入，而程序总得拿它去查数据库、拼文件路径、执行命令、判断权限。
每一次"把外部数据当成可信的东西用"都是一个跨越点，没被检查的地方就是漏洞。

| 数据被当成 | 漏洞类型 |
| --- | --- |
| 代码 | SQL 注入、命令注入、模板注入、反序列化 |
| 身份 | 认证绕过、越权（水平/垂直）、JWT 伪造 |
| 路径 | 目录穿越、任意文件读、文件上传 |
| URL | SSRF、开放重定向 |
| 规则 | 金额、数量、状态机的逻辑漏洞 |
| 环境 | 配置错误、默认口令、组件依赖漏洞、信息泄露 |

所以边界不在工具，在能不能指着某处说：这里有一次信任跨越，而且它没被检查。
Burp、sqlmap 这些工具做的事，只是把这类判断放大——替你反复发请求、看回显。
