## 一、dirsearch 是什么？

**dirsearch** 是一个用 Python 编写的 **Web 路径/目录爆破工具**。  
简单说：它通过**枚举**常见的目录和文件名，去探测目标网站上是否存在这些资源。

---

## 二、第一性原理：我们为什么要“爆破”目录？

一个网站通常有不止你看到的那些页面。开发者可能遗留了：
- 后台管理入口 `/admin`
- 备份文件 `/backup.zip`
- 测试接口 `/test.php`
- 隐藏的 API `/api/v1/`
- 编辑器目录 `/editor/`

这些路径如果没有被链接公开，就需要我们用**字典枚举**的方式去猜测。dirsearch 做的就是这件事：它拿着一份常见的路径列表，逐个向目标服务器发送请求，然后根据 HTTP 状态码（200、403、301 等）判断该路径是否存在。

---

## 三、工作原理（核心）

1. **输入**：目标 URL（如 `http://example.com/`） + 字典文件（包含大量目录/文件名）。
2. **过程**：对字典中的每一个条目，拼接成完整 URL（例如 `http://example.com/admin`），然后发送 HTTP 请求。
3. **输出**：根据响应状态码（200/301/403/401/500 等）判断该路径是否可访问，并筛选出有趣的条目（通常是 200、403、301 等）。
4. **优化**：
   - 支持多线程（加快速度）
   - 自动处理重定向
   - 可根据响应内容大小或关键词排除假阳性
   - 支持递归扫描（在找到的目录下继续深入）

---

## 四、为什么在 CTF / 渗透测试中必须用它？

- **信息收集是第一步**：很多漏洞的入口就是被遗忘的敏感目录或备份文件。
- **速度快**：手工逐个测试不现实，自动化工具是必备。
- **字典专业**：dirsearch 内置了根据大量实战经验整理的高效字典（如 `common.txt`、`directory-list-lowercase-2.3-medium.txt` 等）。

---

## 五、安装与准备

Kali Linux 默认已安装 dirsearch。如果未安装：
```bash
sudo apt update
sudo apt install dirsearch -y
```
或者从 GitHub 获取最新版（推荐，因为字典会更新）：
```bash
git clone https://github.com/maurosoria/dirsearch.git
cd dirsearch
```

运行 dirsearch 时，你需要进入其目录，或将其路径加入 PATH。

## 六、基本用法（从零开始）

### 1. 最简单的扫描
```bash
dirsearch -u http://example.com
```
这会对目标进行默认配置的扫描（使用内置字典，线程数默认 25，只显示状态码 200 的路径）。

### 2. 常用参数解释

| 参数                | 说明                                                  |
| ----------------- | --------------------------------------------------- |
| `-u <URL>`        | 指定目标 URL                                            |
| `-e <扩展名>`        | 追加扩展名列表，例如 `-e php,html,txt`。这样除了扫描目录，还会测试这些扩展名的文件。 |
| `-w <字典路径>`       | 指定自定义字典文件                                           |
| `-t <线程数>`        | 设置线程数（默认 25）。越大越快，但可能触发防护。                          |
| `-x <状态码>`        | 排除某些状态码，例如 `-x 403,404` 就不会显示这些。                    |
| `-i <状态码>`        | 只显示特定状态码，例如 `-i 200,301,403`                        |
| `--recursive`     | 递归扫描（在发现的目录下继续扫描）                                   |
| `-r`              | 递归扫描（简写）                                            |
| `-H <Header>`     | 添加自定义请求头（如 `-H "User-Agent: Mozilla/5.0"`）          |
| `--proxy`         | 使用代理                                                |
| `-o <文件>`         | 保存结果到文件                                             |
| `--simple-report` | 只输出发现的路径，不显示额外信息                                    |

### 3. 示例：扫描一个靶场
```bash
dirsearch -u http://node4.anna.nssctf.cn:29523 -e php,txt,zip -t 30 -x 404
```
- 目标：`http://node4.anna.nssctf.cn:29523`
- 额外测试扩展名 `.php`、`.txt`、`.zip`
- 30 个线程
- 排除 404 状态码（只显示存在的路径）

## 七、如何读懂输出

dirsearch 的输出类似：
```
[13:00:01] 200 -  145B  - /index.php
[13:00:02] 301 -  310B  - /admin  ->  /admin/
[13:00:03] 403 -  289B  - /config/
[13:00:04] 200 -   12KB - /backup.zip
```

- **状态码**：200 表示成功（文件存在），301 是重定向（通常是目录），403 表示禁止访问（但目录存在）。
- **大小**：可帮助判断是否是假页面（如 404 自定义页面也可能返回 200）。
- **路径**：重点关注 `/admin`、`/backup`、`/upload`、`/config`、`.git/`、`.svn/` 等。

## 八、实战技巧

### 1. 选择恰当的字典
dirsearch 的默认字典在 `db/` 目录下。常用的有：
- `directory-list-lowercase-2.3-medium.txt`（中等长度，适合通用）
- `common.txt`（小而精）
- `small.txt`（快速测试）

你也可以用 `seclists` 项目中的大字典（需要单独安装）。

### 2. 避免被封锁
- 不要用太高的线程数（尤其对靶机可用 10-20）。
- 可以添加随机 User-Agent 或延迟：`--delay=0.5`。

### 3. 结合其他工具
扫描结果中的目录，可以用 `gobuster` 再深入扫描，或直接浏览器访问查看。

### 4. 在 CTF 中常见用法
- 发现后台入口（如 `/admin`）后尝试弱口令。
- 发现备份文件（如 `.sql`、`.zip`）下载后可能包含数据库信息或源码。
- 发现 `/git/` 或 `/svn/` 泄露，就用 dvcs-ripper 去拉取源码。

---

## 九、注意事项

- **合法使用**：只对你有授权的目标进行扫描（如自己搭建的靶场、CTF 题目环境）。
- **不要暴力**：大规模扫描公网网站可能违反服务条款，甚至触法。
- **理解状态码**：有些网站会对不存在的路径返回 200（自定义 404 页面），需要根据页面大小或关键词判断。

---

## 十、总结

dirsearch 的本质是 **暴力枚举 Web 路径**。  
你给它一个目标和一个字典，它替你发送成千上万个请求，帮你找出那些隐藏的入口。  
对于蓝桥杯网络安全赛道，它是信息收集阶段不可或缺的工具。熟练使用后，你会更快找到突破口。

现在，你可以在自己的 Kali 上打开一个靶场（比如 Pikachu），试试 `dirsearch -u http://127.0.0.1/pikachu`，看看能扫出什么。慢慢地，你会习惯用它来探索每一个目标。
