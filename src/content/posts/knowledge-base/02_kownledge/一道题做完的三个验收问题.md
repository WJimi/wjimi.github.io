# 一道题做完的三个验收问题

## 来源
复盘 [[Web 安全 8 周目标]] 时，发现「做完了」和「能讲出来」之间没有验收动作。

## 它解决的问题
一道题要怎样才算真的做完，而不是只是抄通了 WP？

## 待答问题
- ❓ 拿 sqli-labs 里做过但合上笔记的三关，各写三行（输入从哪来 / 哪一行变成 SQL 语法 / 什么条件下不成立），哪一关写不出来？
- ❓ SXCTF 那四题，逐题指出信任跨越点，能归到 [[Web 安全的边界在哪]] 表里的哪一行？归不进去的那题说明什么？
- ❓ 脱稿讲一遍和照着 WP 讲一遍，讲出来的东西差在哪一句上？

## 事实
- 三条：成因（输入从哪来、经过谁、以什么权限执行）；边界（什么条件下不成立）；复述（不看 WP 能不能讲出前两条）。
- 纲要第 13 节把掌握分四级：能解释 / 能使用 / 能排错 / 能迁移。「能做出来」只落在第二级。
- 边界这一条的已知例子在 [[Web 安全的边界在哪]]：每次「把外部数据当成可信的东西用」都是一个跨越点。

# Codex分析
## 一、行业环境变了，但变的是哪一层要分清

我不打算给你「都一样，放心学」这种空话，也不打算假装我有 2026 年最新的招聘行情数据——那部分我的信息是有截止点的，需要具体数据我可以去查。但结构性的东西可以讲清楚：

**会过期的**：具体漏洞、具体框架版本、具体 CVE、工具参数、payload 写法。这些东西三五年换一批，学长博客里那些「取反构造无字母 RCE」的招式，有一半在真实业务里根本用不上，它们的作用是训练你的思维，不是技能清单。

**不会过期的**：机制层。HTTP 与会话、认证与鉴权、输入从哪来、经过谁的处理、以什么权限执行、边界在哪。这层东西十年前是这些，现在还是这些。

**还在升值的一层**：环境能力。会不会用 Docker 复现漏洞、会不会搭多网段拓扑把内网题在本地演一遍——这一层近十年只升不降，而且 AI 帮不了你太多。

至于「这个都不会根本不算网安入门选手」这句话，它真实指向的其实是**基础层**：能抓包读包改包、能读懂一段后端代码、能说清一个漏洞从输入到影响的完整链路、能独立复现一个环境。它**不是**在说你得记住 CC 链的 gadget。换句话说，你那句焦虑里真正被击中的部分（「不知道漏洞在整个网站下的成因和边界」），恰好就是这句话的靶心——你的直觉是对的，不是你想多了。

## 二、这本教程的含金量：我核实过的证据

300 个 markdown 文件、69MB；Web 方向 59 篇，知识点/payload 标签 153 篇；方向覆盖 MISC/Crypto/Web/Reverse/Pwn 五大方向之外，还有 AWD、AI 安全、区块链、IoT、工控、应急响应、云、数据安全。仓库最近提交是 2026-09-21，每天自动更新赛事数据，同时有人在做文档修订——是活的。

比规模更值钱的是它的组织方式，恰好都在治你的病：

- 每章按「原理 → 最小示例 → 典型例题」写，例题涉及的前置知识**直接标出对应章节名**，你可以跳过去补那一小块再回来；
- 难点章标 `*`，明确告诉你前期可以跳过；
- `hc-web/index.md` 的导语直接说：不提倡硬啃完前端或某门语言再做题，并把 PHP 特性定为整个教程的**枢纽章**，理由是它会反复出现在 SQL 绕过、文件上传绕过、无参 RCE、WAF 绕过里；
- 它给了你缺的那个全局视角：环境能力「会搭 → 会打 → 会逃」，比赛趋势「解题赛 → 多层网络渗透」，配套还有立足(foothold)、三层网络、横向(lateral)、域基础、云与容器这一整条链路章；
- 附录里有《提问的智慧》和推荐书单。

**唯一的警告**：`hc-skill` 那 153 篇是「知识点 + payload 速查」，那是当字典翻的，不是拿来通读的。你要是从第一页顺读，会掉进另一个坑。

所以回答你的问题：可以当指南，而且**在你这个阶段它比学长的博客更合适**。学长博客是输出记录，他已经过了你正在过的这一段；这本是有前置关系、有配套题、有索引的教程。学长那份 index.md 让你一定看完的正是它的敏感信息泄露章——他其实是在把你往这本书里推。

## 三、关于你的焦虑，我说点可能不太好听的

你的自我诊断「韧性低不够刻苦」是错的。不是因为你其实很刻苦，而是因为**这个诊断不可证伪，也没法指导任何行动**。知道自己不够刻苦之后你能做什么？什么都做不了。这跟「我太笨了」是同一类诊断。

真实的情况是这样：你「每次只学到一角」的感觉不是错觉，而是**把"题"当作学习单位**的固有性质。一道题只暴露一个考点，它天然不会暴露这个漏洞在整个系统里的成因和边界——因为出题人就是只考那一点。所以你反复感到「只学了一角」是必然的，不是你不适合干这个。

但你的应对方向反了。你想通过「先把 PHP 学扎实」「先建立全局视角再动手」来消除这种不安。这在 CTF 里做不到，代价还极高——Hello-CTF 导语明确反对这条路，理由是很实际的：你花三个月啃完 PHP，回来做题还是不会，因为你缺的从来不是 PHP 语法，是「这道题在考什么」的判断力。

真正能消掉「一角感」的，是**每道题之后强制补一条边**，把这一角挂回系统上：

1. 题做完，逼自己用一句话回答：这个漏洞的**成因**是什么，**边界**在哪（它在什么条件下不成立）。
2. 一次只挂一条链——输入谁接收 → 经过什么处理 → 以什么权限执行——不要求覆盖整个网站。
3. 验收标准是「不看 WP 能不能复述出来」，而不是「我做出来了」。

答不出第 1 条，说明这道题你只是抄通了，那就是缺口所在，而且是**定位精确**的缺口——它是「这一类机制的哪一环」，不是「我 PHP 不行」这种笼统的缺口。你的受挫感有很大一部分来自把精确缺口误报成笼统缺口，然后每次都要补一大片来求安心。

最后一句实话：刷题量确实逃不掉。学长 11 个月 101 篇，平均每 3 天一篇输出，倒推回去刷题量只会更多。这一点上没有捷径，能优化的只有「别在错的方向上刷」。

***

按你们那套学习系统收个尾：这次解决了「cwd 是什么、值不值得用」，理解了「行业里变的是技术点层，不变的是机制层，而你的焦虑精确落在机制层」，新产生的问题是你现在卡的那道 RCE 题到底属于哪一类机制缺口。

下一步最重要的问题，我想问你一个具体的：**你最近卡住的那道 RCE 题，你能说出它的「输入 → 处理 → 执行」链路走到哪一步断了吗？** 如果能说出断点在哪，我们就用 Hello-CTF 对应的那一章去补，补完你复述一遍；说不出来，那我们要先解决的是「怎么观察一道题」。
