# CTF 的 Web 和实战差在哪

## 来源

打 SXCTF、做完 sqli-labs 前 30 关、自己出了 IVN 那道注入题之后，
一直在问：这些和真实工作到底差多远？

## 它解决的问题

CTF 的 Web 方向和实际任务，练的是不是同一件事？

## 当前理解

底层同一条：**理解程序怎么处理输入**。差别在这条底层之上，各练了什么。

| | CTF Web | 实战 |
| --- | --- | --- |
| 漏洞哪来的 | 出题人放好的 | 自己判断，通常藏在很无聊的地方：老框架、默认口令、忘了关的接口、配置错误 |
| 目标 | 拿 flag，有唯一解 | 没有 flag，也没有唯一解，要自己判断影响和优先级 |
| 代价 | 打错重来 | 可能把线上搞挂，有授权边界 |
| 节奏 | 几小时到几天，有提示 | 几周到几个月，没人给提示 |
| 练什么 | 识别模式 + 熟练利用 | 从一团混杂信息里判断哪些重要，再加授权、沟通、报告 |

给厂商报一个漏洞和拿一个 flag 是两件事：前者要能说清影响、复现步骤、修复建议，
还要在修复之前闭嘴。

所以 CTF 不是实战的缩小版，是实战的**单项训练**——它把"识别和利用"练到很熟，
另外几项完全不练。

## 实践

修 SXCTF 那道二维码题用的就是 CTF 味：目标明确、有唯一解、打错重来。
真实工作里更常见的开头反而是"这个接口没人管，但它能读到别人的数据"，
第一件要做的事是先判断值不值得往下走。
