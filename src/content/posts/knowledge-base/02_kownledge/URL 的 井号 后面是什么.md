# URL 的 # 后面是什么

## 来源

拼 BUFF 的筛选链接时撞上的：把筛选条件（磨损区间、价格区间、排序）配好，
地址栏里确实全都带上了，可这个 URL 直接请求回来却是没有任何筛选结果的页面。
背景见 [[knowledge-base/03_projects/automation/tradeup-material-sourcing|CS2 炼金配方的自动取材]]。
（这篇笔记中途改过一次结论，错的推导过程也留在里面——翻车比正确更值得记。）

## 它解决的问题

一个 URL 里哪部分是「发给服务器的」，哪部分「只活在我这台机器上」？
搞不清这个，就会以为「把参数写进 URL = 把条件交给服务器」，然后在爬虫里反复踩同一个坑。

## 当前理解

一个 URL 分成几段，它们的去向完全不同：

```text
https://buff.163.com/goods/1115547 ?from=market #tab=selling&min_price=1&min_paintwear=0.28
└──────┬─────────┘└─────┬──────┘└────┬─────┘ └──────────────┬──────────────────┘
     连哪台机器         路径+查询串             片段 fragment
                    （发给服务器）        （浏览器自己留着，从不发给服务器）
```

关键那一条：**`#` 后面的内容永远不会出现在 HTTP 请求里。**
不管片段怎么改，服务器收到的请求一模一样。

所以「参数在 `#` 后面」意味着 **筛选是页面里的 JavaScript 自己算的**：
脚本读 `location.hash`，拆出参数，然后（多半）再发一个自己的 XHR 去要数据。
服务器从来没看到你选了哪些筛选条件。

推论（这次踩到的坑就是它）：

- 这种 URL 能用浏览器打开成「筛选好的页面」——因为浏览器把片段给了 JS。
- 但 `requests` / `curl` 这类工具拿到的是**没跑 JS 的空壳**，筛选结果一个都没有。
- 而且这跟 `requests` 的写法无关：任何 HTTP 客户端都不发送片段，这是协议本身的规定。

那正确的两条路：

| 想要 | 怎么做 |
| --- | --- |
| 只想拿到筛选后的数据 | 开发者工具里找到 JS 实际发出去的那个 XHR，直接请求它 |
| 想要「页面变成筛选后的样子」 | 用真实浏览器（Playwright / Selenium）打开 URL，让 JS 跑完 |

顺带解释了一件常见的事：前端 hash 路由的页面，链接分享给别人还能还原出同一个视图——
还原动作发生在对方的浏览器里，服务器完全不知道你们在看哪一页。

### 补一层：参数"在 URL 里"和"被读了"是两回事

2026-09-28 在 BUFF 上踩到的：把 `min_paintwear=0.18&max_paintwear=0.21` 写进地址栏，
页面照常打开，看着像那么回事——但列表里第一行的磨损是 `0.3461`，压根没被筛。

读它的前端脚本才看明白：构造请求时它读的键叫 `float_range`，
读不到就把磨损范围置空（= 不筛）。`min_paintwear` / `max_paintwear` 只是用来**回填界面**的。

所以又多一条检查习惯：**别用"参数出现在 URL 里"当作筛选生效的证据。**
真的证据只有两种——看结果数据对不对，或者去读那段代码读了哪个键。

### 再补一层（同一天，同一个参数的更正）

上面那条结论后来又被打脸了：同样的参数，在**已经登录**的浏览器里打开时**是生效的**——
列表 10 行全部落在区间内。

差别在于中间发生过一次跳转：第一次是打开页面才发现没登录，**人在窗口里登录**，
跳转时 `#` 里的参数丢了，落回来的是未筛选的原始列表。

于是同一条 URL 有两种结果，而差异来自"这段 `#` 有没有活到页面渲染那一刻"。
**片段是易失的**：它不进 HTTP 请求，一次跳转、一次 login 回调，就可能不再是你出发时那串。

所以对 `#` 里的参数，正确的期待是：它能还原视图，但**别指望它在任何跳转之后仍然有效**。
需要它稳定，就得在页面真正渲染之前确认它还在。

## 实践

2026-09-27：拿到一条 BUFF 商品页的筛选链接：

```text
https://buff.163.com/goods/1115547?from=market#tab=selling&min_price=1&max_price=31&page_num=1&sort_by=price.asc&min_paintwear=0.28&max_paintwear=0.35
```

`goods_id` 在路径里（发给服务器），磨损区间和排序全在 `#` 后面（不发）。
结论：这个项目的执行端必须用真实浏览器，不能是纯 HTTP 客户端。
